# Energine Simple — новая визитка

Как выпустить сайт-визитку для клиента: установка, страницы из готовых шаблонов, свои цвета, проверка. Установка
и площадка подробно — в `docs/INSTALL.md`; здесь — порядок работы над новым сайтом.

Обозначения, как в `docs/INSTALL.md`: `H` — каталог площадки, `R=$H/private/energine` — репозиторий, команды —
от владельца площадки (`runuser -u <владелец>`).

## 1. Установка без демо

Развёртывание и установка — шаги 1–4 раздела «Развёртывание» в `docs/INSTALL.md`:

```sh
cd $H/web && runuser -u <владелец> -- php8.5 index.php setup install --domain=<домен> \
  --db-name=<база> --db-user=<пользователь базы> --admin-email=<e-mail администратора>
```

Демо-контент (`setup demo`) на сайт клиента не ставится: после установки сайт пуст — главная, вход,
регистрация, восстановление пароля и админка.

## 2. Страницы из шаблонов

Войдите администратором (`/login/`), откройте «Административная часть → Управление структурой».

- **Главная** — выбрать главную страницу и «Редактировать», поле «Содержимое страницы» — «Лендинг»
  (`main/landing.content.xml`): первый экран, услуги, отзывы, призыв к действию, контакты.
- **Страница услуги** — «Добавить» под главной, «Содержимое страницы» — «Услуга» (`main/service.content.xml`):
  первый экран, описание, цены, вопросы и ответы, призыв.
- **Контакты** — «Добавить», «Содержимое страницы» — «Контакты» (`main/contacts.content.xml`): заголовок и текст
  страницы, контакты.

Остальные страницы — обычный текст («Текстовая страница»), список подразделов, карта сайта.

Свой шаблон из секций — одной командой:

```sh
cd $H/web && runuser -u <владелец> -- php8.5 index.php setup page --name=about --title="О компании" \
  --sections=hero,services,reviews,cta
```

Она создаёт `site/modules/main/templates/content/<имя>.content.xml` (здесь `about.content.xml`), дописывает название `CONTENT_ABOUT` в
`site/modules/main/translations.php` и раскладывает статику — шаблон сразу есть в списке «Содержимое страницы».
Файл шаблона дальше правится руками: компоненты — короткими именами (`class="TextBlock"`), секции — `section`
(раздел «Шаблоны страниц и секции» в `docs/INSTALL.md`).

Переводы сайта (названия шаблонов, образцы секций) — `site/modules/main/translations.php`; после правки —
`setup translations` (добавляет недостающее, правленое в админке не трогает). Найти подписи без перевода —
`setup untranslated`.

## 3. Тексты секций

Тексты правит владелец прямо на странице: «Режим редактирования» на панели администратора. Пустая секция посетителю
не видна, администратору показывает пример — его достаточно поправить. Какая разметка как оформляется (заголовок,
список карточек, цитата, кнопка-ссылка) — таблица в разделе «Шаблоны страниц и секции» `docs/INSTALL.md`.

Картинки — кнопкой «Изображение» редактора (файлы — в репозитории файлов админки). Картинка в первом экране
становится фоном полосы.

## 3а. Что подсказать владельцу

- **Битые ссылки** — «Административная часть → Битые ссылки» (`/admin/links/`): ссылки в текстах на удалённые или
  отключённые страницы и отсутствующие файлы, со страницей и причиной. То же в консоли — `setup checklinks`
  (выход 1, если битые есть). Ссылки на страницы только для вошедших (например, в админку) показываются отдельно.
- **Подсказка «?»** в правом верхнем углу окон админки (страница, пользователи, файлы, переводы, настройки, письма)
  объясняет, что делать на экране. Текст — константа `HELP_<КЛАСС>_<СОСТОЯНИЕ>` в «Переводах».
- **История текста** — в режиме правки у каждого блока в панели редактора есть «История»: прежние версии (кто,
  когда, начало текста), «Посмотреть» и «Вернуть». Хранится до 20 версий на блок и язык; каждое сохранение видно в
  «Журнале» и в дате страницы (sitemap.xml).
- **Ссылка на страницу сайта** — кнопка с цепочкой в редакторе: страница выбирается из дерева, адрес ставится
  полный (с языком), текст — выделение.
- **Язык «в подготовке»** — «Языки» → снять «Открыт посетителям»: тексты на нём готовят редакторы, посетители
  языка не видят (адреса — 404, в переключателе его нет). Язык по умолчанию закрыть нельзя.
- **Памятка владельцу** — `setup manual --out=ФАЙЛ` (из `docs/OWNER.md`, с адресами площадки): отдайте её вместе
  с доступом.

## 4. Свои цвета и шрифт

Все цвета, шрифт, скругление и ширина страницы — в одном файле
`site/modules/main/stylesheets/theme.css`: светлая схема на `:root`, тёмная — в `@media (prefers-color-scheme: dark)`.
Имена переменных не меняются, меняются значения:

- `--accent` / `--accent-fg` — основной цвет (ссылки, кнопки, полоса призыва) и текст на нём;
- `--bg`, `--bg-soft`, `--fg`, `--muted`, `--border` — фон, фон полос, текст, приглушённый текст, линии;
- `--danger`, `--danger-bg`, `--ok-bg`, `--field-bg` — ошибки, успех, фон полей;
- `--font`, `--radius`, `--wrap` — шрифт (только системные или свои файлы — без сторонних адресов), скругление,
  ширина страницы.

После правки — пересборка стилей (бинарник Tailwind — `tools/get-tailwind.sh`):

```sh
bash $R/tools/get-tailwind.sh          # один раз на машине разработчика
cd $H/web && runuser -u <владелец> -- php8.5 index.php setup css
```

Контраст текста и кнопок — не ниже 4.5:1 в обеих схемах.

## 5. Проверка

- `tests/css-build.sh` — собранный `main.css` совпадает с исходниками (иначе забыли `setup css`);
- аудит темы `tests/audit/theme.js` — контраст обеих схем, ширина от 320 px, меню, формы
  (запуск — `tests/README.md`);
- обход `tests/audit/crawl.js` — нет ошибок JS и 404 на страницах.
- `setup check` — перед сдачей: отладка, адрес, демо-пользователи, `robots.txt`, названия страниц на открытых
  языках, битые ссылки, непереведённые константы (код выхода 1 при FAIL).

## 6. Перенос на хостинг

Собранный `site/modules/main/stylesheets/main.css` лежит в git: хостингу бинарник Tailwind и Node не нужны.

1. На хостинге — шаги «Развёртывания» из `docs/INSTALL.md` и `setup install` в пустую базу: установщик пишет
   конфиг площадки (`configs/system.config.<домен>.php` и ссылку `web/system.config.php`) и создаёт
   администратора.
2. База стенда — тексты, страницы и пользователи: дамп базы стенда загружается в базу хостинга поверх только что
   установленной (таблицы те же). Администратор и пароли — из стенда.
3. Загруженные файлы — каталог `web/uploads/` стенда копируется в `web/uploads/` хостинга (картинки из
   редактора и репозитория файлов), владелец — пользователь площадки.
4. Статика — `setup linker` от владельца площадки.

## 7. Свой код

Если визитке понадобился свой компонент или запрос к базе:

- База — методы `Db` у `E()->getDB()`: `rows()`, `row()`, `scalar()`, `column()` для чтения; `exec()`, `insert()`,
  `update()`, `delete()`, `transaction()` для записи — везде с параметрами `?`, без склейки значений в строку запроса.
  Прежние `select()`, `modify()`, `getScalar()` остаются. При отладке каждый запрос виден в `document/@queries`
  (`docs/INSTALL.md`, «Ошибки и отладка»).
- Тип поля в конфиге компонента — значение `FieldType` (`string`, `integer`, `select`, `file` …); неизвестный тип —
  ошибка разработчика с именем поля, а не странное поле в форме.
- Объекты ядра — типизированные методы реестра: `E()->getDB()`, `E()->getLanguage()`, `E()->getUtils()`,
  `E()->getTranslator()`, `E()->getUserGroup()`, `E()->getFileRepoInfo()`; обращений вида `E()->Имя` в коде нет
  (`tests/registry.php` следит).
