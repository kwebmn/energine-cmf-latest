# new.energine.org — установка Energine

Состав демо-стенда и что было исправлено ради него — в `DEMO-new.energine.org.md`.

Установлено 2026-09-13, модули mail, ads, blog и shop подключены 2026-09-14. Ядро: [energine-cmf/energine](https://github.com/energine-cmf/energine) `master@10191215` (2018-05) + локальная ветка `new.energine.org`.
Окружение: nginx (ISPConfig, конфиги не менялись), **PHP-FPM 8.5** (пул `web93`; 2026-09-13 переведён с 7.0), MariaDB 10.11, база `c1newenergine`.

## Раскладка

Document root ISPConfig фиксирован (`web/`), а `open_basedir` пускает только в `web/`, `private/`, `tmp/`.
Поэтому стартер разложен так:

| Путь (от `/var/www/clients/client1/web93`) | Что это |
|---|---|
| `web/` | htdocs Energine: `index.php`, `bootstrap.php`, `auth.php`, `resizer/`, `uploads/` |
| `web/system.config.php` | симлинк на `private/project/configs/system.config.new.energine.org.php` (права 600) |
| `web/images`, `scripts`, `stylesheets`, `templates`, `system.jsmap.php` | генерирует `setup linker` / `scriptMap`, руками не править |
| `private/energine/` | ядро, git-клон, ветка `new.energine.org` |
| `private/project/` | проект (стартер): `configs/`, `core/modules/*` (симлинки на ядро), `site/modules/main`, `vendor/`, `setup/`, `sql/`, `cli/` |

Всё принадлежит `web93:client1`: в vhost стоит `disable_symlinks if_not_owner`, и nginx отдаёт файл по симлинку, только если у ссылки и цели один владелец.
Команды ниже запускать от `web93` (`runuser -u web93 -- ...`), иначе файлы и симлинки получат владельца root.

Вход в админку: `demo@energine.org` / `demo` (по решению владельца, см. «Риски»).

### Ядро (`git -C private/energine log master..new.energine.org`)
Установка:
1. `[seo]` robots.txt и Google sitemap брали XSLT по `'../core/...'` → `CORE_REL_DIR`.
2. `[QAL]` `call()` проверял `rowCount()` вместо `columnCount()`: после загрузки файла админка показывала «SQLSTATE[HY000]: General error» (MariaDB отдаёт affected rows для `CALL`).
3. `[user]` убран behavior `MoveToFooter`, JS-файла которого в апстриме нет: ReferenceError ломал JS гостям (опрос на главной).
4. `[apps]` лента не заполняла URL категории: ссылки на новости были без `news/` и отдавали 404.

PHP 8.5 и строгий режим MariaDB:
5. `[php8]` обработчик ошибок совместим с PHP 8 (без `$errcontext`); таймзона `Europe/Kyiv` (`Europe/Kiev` в системных tzdata PHP 8.5 недействительна, даты молча уезжали в UTC).

## Модули mail, ads, blog, shop

| Модуль | Сайт | Админка |
|---|---|---|
| mail | `/subscribe/` — подписка по e-mail; `/subscriptions/` — «Мои подписки» (зарегистрированные) | «Шаблоны писем», «Рассылки» (вкладки подписанных пользователей и e-mail), «Подписчики рассылок», «Сообщения рассылки» |
| ads | виджет «Баннер» (добавляется в режиме редактирования страницы); `/banners/` — скрытый корень рубрик баннеров | «Баннерные места», «Баннеры» |
| blog | `/blogs/` — последние записи, записи блога, день/месяц по календарю, запись с комментариями | «Блоги» → «Записи блогов», «Комментарии блогов» |
| shop | `/catalog/` (категории `/catalog/phones/`, `/catalog/laptops/`, `/catalog/audio/`), `/search/`, `/cart/`; `/wishlist/` и `/my-orders/` — зарегистрированные | «Магазин»: товары, категории, заказы, характеристики и их группы, производители, акции, статусы заказов, доставка, оплата, валюты, магазины, страны |

**Почта.** Регистрация, восстановление пароля, обратная связь и формы конструктора отправляют письма через `mail()` PHP (sendmail сервера, пул задаёт отправителя конверта `webmaster@new.energine.org`), заголовок From — `mail.from`. Тексты — в «Шаблонах писем», макросы перечислены в подсказке шаблона; в HTML-части значения макросов экранируются (разметку в них писать бесполезно), в текстовой — подставляются как есть.
Капчи на сайте нет (удалена 2026-09-14): регистрация, обратная связь, формы конструктора и анонимные комментарии к новостям отправляются без неё.
Куда уходят уведомления: обратная связь — «Обратная связь» → «Получатели»; формы конструктора — поле e-mail адресов формы, если оно пусто — `mail.manager`. Сейчас везде демо-адрес `demo@energine.org`.

**Рассылки.** Рассылка (тип `news` — новые новости, `crm` — «Сообщения рассылки») отправляется обработчиком по своему периоду; cron не настроен. Запуск (например, раз в час через Cron Jobs ISPConfig):

```sh
runuser -u web93 -- php8.5 /var/www/clients/client1/web93/private/project/cli/mail_sender.php run
```

При `site.debug = 1` обработчик ничего не отправляет, а дописывает письма в `web/uploads/tmp/mailout.txt` (см. «Риски»).

**Баннеры.** Баннерное место (системное имя, размер) → баннеры (картинка со ссылкой или HTML-код, сайты, рубрики, порядок, активность). Виджет берёт баннеры места из параметра `type` (по умолчанию `sidebar`, 240×400), `limit` и `order` (`rand` или по порядку).

**Блоги.** Блог создаёт администратор («Блоги», поле пользователя); владелец блога видит на `/blogs/` ссылку «Новая запись» и правит свои записи, администратор — любые. HTML записей с сайта чистится (скрипты, обработчики, `javascript:`); комментарии — только зарегистрированным.

**Магазин.** Категории — разделы под `/catalog/` (тег `catalogue`), создаются в «Категориях» с набором характеристик; товары — в «Товарах» (цена, производитель, наличие, характеристики, изображения, похожие товары). Корзина работает для гостей, избранное — для зарегистрированных. Заказы создаются в админке (см. «Риски»); «Мои заказы» показывает заказы, привязанные к пользователю.

## PHP 8.5: что важно знать
- **Обработчик ошибок** (`share/gears/ini.func.php`): deprecation только пишутся в лог (`PHP Deprecated: ...` в `/var/log/ispconfig/httpd/new.energine.org/error.log`) и не ломают запрос; предупреждения и уведомления, как и раньше, становятся `SystemException`, но теперь дополнительно логируются с исходным файлом и строкой (`PHP error N thrown as SystemException: ...`). После обновления PHP или ядра смотрите этот лог.
- **PDO**: с PHP 8.1 MySQL при эмулированных prepared statements отдаёт числа как `int`/`float`; включён `PDO::ATTR_STRINGIFY_FETCHES`, чтобы код получал строки, как на 7.0.
- **`QAL::modify()`**: `null` пишется как `''`, значения, нестрого равные `''`, — как NULL. В PHP 8 `0 == ''` ложно, поэтому целый `0` теперь пишется как `0`, а не NULL. Где нужен NULL — передавайте NULL-семантику явно (в текущем коде таких вызовов не найдено).
- **tidy** для PHP 8.5 не установлен: чистка HTML текстовых блоков (`site.aggressive_cleanup`) молча пропускается. Вернуть: `apt install php8.5-tidy` (перезагрузит php8.5-fpm, на нём ещё 12 сайтов).
- Как проверено: `php8.5 -l` по всем 256 PHP-файлам (ядро, setup, cli, web) — чисто, без устареваний времени компиляции; PHPStan уровня 5 с правилами deprecation по всем модулям; Rector-правила устареваний PHP 8.0–8.5 (null-ключи, `$escape` CSV-функций, `setAccessible`, `${}`, `get_class()` без аргументов, обратные кавычки, `case ...;`, `__sleep`/`__wakeup` и др.); `composer check-platform-reqs` под 8.5.10; на живом сайте — все публичные страницы ru/ua и страницы админки, гриды всех редакторов, формы, запись и удаление (разделы, новости, переводы, пользователи, файлы, опросы, режим редактирования), сохранение форм редакторов без изменений, конструктор форм (все типы полей, значения списков, результаты, удаление), регистрация, восстановление пароля, обратная связь и формы с проверкой писем в локальном ящике сервера (включая экранирование разметки, кавычек и `&` в HTML-части), анонимные комментарии, модули mail (редакторы, вкладки, подписка, «Мои подписки», обработчик рассылок), ads (места, баннеры, виджет, вывод), blog (редакторы, ленты, календарь, пагинация, форма владельца, права, комментарии), shop (справочники, характеристики, категории, товары, каталог, фильтр, поиск, корзина, избранное, заказы, акции, удаление). Headless Chrome: 166 страниц и форм (все страницы гостем на ru/ua и администратором, формы добавления и правки всех гридов) — ошибок JS нет. Компоненты, не размещённые на страницах, отрендерены через конструктор виджетов (см. ниже). В логе PHP после всех сценариев сообщений нет.
- Не проверялось в работе: FTP-репозитории файлов; доставка писем во внешние почтовые ящики (по решению владельца проверялась только локальная доставка).

- Opcache FPM 8.5 перечитывает файлы раз в 2 секунды — перезапуск после правок не нужен.
- В журнале nginx регулярно появляется `[crit] openat() "…/web/" failed (13: Permission denied)`. Это не поломка: каталог сайта у ISPConfig имеет режим 0710, а nginx на каждом запросе пробует вариант `$uri/` из `try_files` и получает отказ на чтении каталога. - `site.cache` не включать: `Cache::CACHE_DIR = '../cache/'` относительно `web/` уходит за `open_basedir`.

## Риски и нерешённое

Закрыто при сборке демо-стенда (подробности в `DEMO-new.energine.org.md`):
загрузка исполняемых файлов, перезапись чужих анонимных комментариев, выдача
всех пользователей с хэшами паролей на странице «Мои заказы», страница 404,
карта сайта для поисковиков, отсутствие сравнения товаров и «недавно
просмотренных» на страницах.

Остаётся по решению владельца:

1. **Пароль администратора опубликован** на главной намеренно: стенд открытый.
   Загрузка исполняемых файлов закрыта, но админ-доступ по-прежнему позволяет
   многое — см. пункты 2–6.
2. **Восстановление пароля** (апстрим) сразу меняет пароль найденного пользователя
   и отправляет новый на его e-mail — без подтверждения. Любой посетитель может
   сменить пароль `demo@energine.org`.
3. **Формы без капчи** (капча удалена по решению владельца): регистрация, обратная
   связь, формы конструктора и анонимные комментарии ничем не защищены от ботов.
   Регистрация и обратная связь отправляют письмо на любой введённый адрес.
4. **Разметка в гридах админки**: гриды выводят значения как HTML
   (`GridManager.js`, `cell.set('html', ...)`). Текст из публичных форм может
   выполнить скрипт в браузере администратора.
5. **Конструктор форм выполняет DDL**, а репозиторий виджетов пишет файлы шаблонов
   в `web/templates/` — и то и другое доступно любому, кто вошёл как администратор.
6. **Удаления в админских гридах каскадные**: удаление языка или сайта необратимо.
7. **Адреса почты — демо**: `mail.from` = `noreply@energine.org`, получатели —
   `demo@energine.org` и адреса `@example.com`. Доставка наружу не проверялась.
8. **Отладочный режим и рассылки**: при `site.debug = 1` обработчик пишет письма
   вместе с адресами подписчиков в `web/uploads/tmp/mailout.txt`, а файл отдаётся
   по HTTP. Перед настройкой cron выключить debug или удалять файл.
9. **Магазин**: оформления заказа на сайте нет как класса задач — заказы заводит
   менеджер; экспорт заказов в Excel не портирован (PHPExcel в зависимостях нет).
10. Непереведённые константы в админке, в основном скрытые поля id.
11. Нет ассетов `images/main/icons.png` и `images/webworks/icons.png` — в
    репозитории их никогда не было. Заглушки картинок ядро берёт с placehold.it,
    браузер их не загружает.
12. `/robots.txt` отдаёт статический файл ISPConfig; компонент доступен по адресу
    со слешем. Конфиги веб-сервера не трогаем.
13. nginx пишет `[crit] openat() ".../web/" failed (13: Permission denied)` — у
    `web/` права 710 от ISPConfig; на работу не влияет.
14. Добавление раздела сдвигает `smap_order_num` на +1 у всех разделов сайта
    (`Grid::saveData()`, апстрим): порядок внутри родителей не меняется, но номера
    со временем растут.
15. `share_session` — таблица в памяти на 16 МБ (около тысячи живых сессий);
    корзина создаёт сессию каждому посетителю.
