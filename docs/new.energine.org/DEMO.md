# new.energine.org — демо-стенд Energine

Стенд показывает возможности CMF: правдоподобный сайт, где каждый модуль работает
на реальных данных, плюс раздел-путеводитель «Возможности» с описанием и ссылками
«где посмотреть» и «где управлять».

Сопутствующие документы: `INSTALL-new.energine.org.md` — установка, правки ядра,
риски; `tests/README.md` — как прогнать проверку стенда.

## Что посмотреть

| Адрес | Что показывает |
|---|---|
| `/features/` | Путеводитель: 13 страниц, по одной на модуль |
| `/` | Текстовые блоки, краткие новости, опрос, подборки вкладками, баннер в шапке |
| `/news/` | Лента, календарь, облако тегов, архив по датам, RSS, комментарии с ветками |
| `/blogs/` | Три блога, календарь, отложенная запись, комментарии |
| `/catalog/` | Три категории, фильтр, сортировка, сравнение, корзина, избранное, валюты |
| `/media/` | Галерея вложений раздела |
| `/admin/` | Админка, вход `demo@energine.org` / `demo` |

Демо-покупатель: `olena@example.com` / `demo` — у него заказы, подписки и блог.

## Воспроизводимость

Порядок импорта с нуля дополнен одним файлом (пункты 1–5 — см. `INSTALL`):

6. `sql/demo.content.sql` — весь демо-контент и страницы путеводителя.

Файл рассчитан на повторный прогон: каждая вставка защищена проверкой
существования, повторный импорт ничего не дублирует.

Проверено: установка с нуля из `sql/*.sql` во временную базу проходит без единой
ошибки, повторный прогон идемпотентных файлов — тоже. Полученная база совпадает
с рабочей по всем 119 таблицам, включая порядок и названия всех 83 страниц.
Отличаются только записи доменов (`https`-запись добавляется вручную при
установке), журнал действий и таблица сессий.

**Файлы изображений в SQL не входят.** При переносе нужен каталог
`web/uploads/public/demo/` — он есть в архиве рядом с дампом в `backup/`.

## Проверка

Сценарные тесты (`tests/regression.sh`): 11 наборов, 0 расхождений,
журнал ошибок PHP за прогон пуст. Наборы правят данные и убирают за собой;
получатели писем на время прогона переключаются на локальный ящик.

Обход браузером (`tests/audit/crawl.js`): 243 адреса — гость на двух
языках, администратор, формы добавления и правки всех гридов. Ни одной ошибки
JavaScript, ни одного запроса с кодом 400+.

## Снимки и откат

В `private/project/backup/` два набора: `*-before-demo-*` — состояние до
наполнения, `*-demo-*` — состояние сданного стенда.

Вернуть стенд к сданному состоянию:

```bash
cd /var/www/clients/client1/web93
zcat private/project/backup/db-demo-*.sql.gz | mysql -uc1newenergine -p c1newenergine
tar xzf private/project/backup/uploads-demo-*.tar.gz -C web/
chown -R web93:client1 web/uploads
```

Откатить демо-данные целиком — те же команды с файлами `*-before-demo-*`.

## Что было исправлено в ядре

Коммиты в ветке `new.energine.org` репозитория `private/energine`.
Ниже — по областям; подробности в сообщениях коммитов.

### Безопасность
- **Загрузка исполняемых файлов.** Файловый репозиторий сохранял имя файла как
  есть, а веб-сервер выполняет любой `.php` под корнем сайта. При опубликованном
  логине администратора это было удалённое выполнение кода. Теперь расширения,
  которые сервер отдаёт интерпретатору, отвергаются.
- **Чужие анонимные комментарии.** Проверка авторства сравнивала `false` с `NULL`
  нестрого, и любой гость мог переписать любой анонимный комментарий.
- **Утечка данных в «Моих заказах».** У компонента не было списка полей, поэтому
  выводились все колонки заказа, а поля-справочники разворачивались целиком —
  на публичной странице оказывались все пользователи сайта с хэшами паролей.

### Не отрисовывалось
Похожие новости, информация о странице, заказы покупателя, недавно просмотренные,
облако тегов, таблица сравнения, оформление раздела, подборки — выводились сырым
списком полей или не выводились вовсе. Добавлены шаблоны.

### Не работало
- Календарь новостей (3 бага), RSS-лента (5 багов), фильтр новостей по тегу.
- Страница 404 показывала главную страницу с кодом 404.
- Карта сайта для поисковиков не создавалась и падала при обращении.
- Профиль сохранял пароль, не совпавший с подтверждением.
- Фильтр товаров типов «радиокнопки» и «список» не отсеивал ничего.
- Цены выводились без валюты, переключателя валют не существовало. Корзина и
  список желаний печатали сырое значение поля даже после появления общего
  шаблона цены, а в режиме single (добавление товара в корзину, таблица
  сравнения) шаблон обрывал преобразование и страница отвечала пустым телом.
- Сравнение товаров, сохранённые фильтры, недавно просмотренные, форма поиска,
  асинхронный блок связанных товаров — не доходили до рабочего состояния.
- Баннеры игнорировали привязку к сайтам и страницам.
- Подборки обращались к несуществующей колонке, брендинг не имел поля в редакторе,
  HTML-врезки страниц не имели таблицы.
- Рассылка отправляла пустые выпуски и повторно рассылала будущие материалы.

### Подписи и порядок
- В админке 124 константы показывались системными именами (`FIELD_TOP_NAME`,
  `TXT_ACTIONSLIST`, `MSG_BAD_INT_FORMAT`) — записей в справочнике просто не было.
  Добавлены на обоих языках; публичная часть таких мест не имела.
- Названия шести разделов, пришедших из исходного дампа, оставались в украинской
  версии русскими.
- Номера порядка разделов верхнего уровня совпадали у четырёх страниц, и меню
  строилось произвольно. Порядок задан явно: сначала содержательные разделы,
  затем личный кабинет, затем служебные страницы.

### Падало вместо ответа
Редактор структуры падал на несуществующем разделе-родителе. Сохранение из
сокращённой формы (категории каталога) обрывалось фатальной ошибкой, а заодно
безусловно переписывало права раздела — форма их не присылает, и права
стирались. Испорченный запрос без вложенного массива переводов валил грид.
Все четыре места теперь отвечают ошибкой или 404.

### Повторяющаяся причина
Половина поломок в магазине объяснялась одним правилом движка: состояния из URL
разбираются только у «активного» компонента страницы. Корзина обходила это
особым приёмом в конструкторе, остальные компоненты — нет. Теперь приём общий.

## Что осталось за рамками

- **Оформления заказа на сайте нет** — в движке отсутствует как класс задач,
  заказы заводит менеджер в админке.
- **Экспорт заказов** в Excel недоступен: метод есть, состояния нет.
- **Видео** не показываем: перекодировка требует ffmpeg, на хосте его нет.
- **`/robots.txt`** отдаёт веб-сервер; компонент доступен по адресу со слешем.
  Конфиги веб-сервера не трогаем.
- **`share\HTMLCap`** — заготовка без логики, шаблона и данных. Её предполагаемое
  назначение (блок сырого HTML) уже закрыто HTML-врезками модуля apps,
  поэтому компонент помечен устаревшим, а не переписан.

## Риски открытого стенда

Логин администратора опубликован намеренно. Закрыто кодом: загрузка исполняемых
файлов и перезапись чужих комментариев. Остаётся принятым риском:

1. Конструктор форм выполняет DDL — посетитель с правами админа может создавать
   и удалять таблицы форм.
2. Репозиторий виджетов умеет писать файлы шаблонов в `web/templates/`.
3. Восстановление пароля меняет пароль немедленно — demo-аккаунт можно заблокировать.
4. Формы, регистрация и обратная связь шлют письма на введённый адрес без капчи.
5. Текстовые блоки и HTML-баннеры выводятся без экранирования.
6. Удаления в админских гридах каскадные и необратимые.
7. `share_session` — таблица в памяти на 16 МБ, около тысячи живых сессий.

Компенсация — снимки базы и файлов в `backup/` и раздел «Снимки и откат» выше.
