# Energine Simple, этап 8, шаг 7 — структура сайта без MooTools, MooTools уходит

Дата: 2026-10-02. Продолжение шага 6 (`docs/superpowers/specs/2026-10-02-energine-simple-stage8-step6-grids-design.md`).
Владелец: «продолжай без остановки» — шаги этапа 8 идут подряд, с выкладкой и проверкой на площадке, без отдельных
согласований.

## 1. Цель

Последние скрипты на MooTools — структура сайта:

| Файл | Строк | Что это | Где |
|---|---|---|---|
| `DivManager.js` | 437 | дерево разделов с панелью: добавить, править, удалить, вверх/вниз, перейти на страницу | структура (`admin/structure/`) |
| `DivSidebar.js` | 73 | то же в боковой панели администратора | боковая панель на страницах сайта и в админке |
| `DivTree.js` | 96 | окно выбора раздела (родитель раздела): «Выбрать», раздел и его потомки — нельзя | окно из формы раздела |
| `getDirsTree.js` | 156 | окно выбора папки для переноса файла | репозиторий, «Перенести в папку» |

После перевода MooTools больше никому не нужна: **`MooCompat.js` и `mootools.min.js` (160 КБ) удаляются**, ни одна
страница сайта и админки MooTools не загружает. Этап 8 (переход с MooTools на чистый JavaScript) на этом заканчивается.
ES-модули (вместо `ScriptLoader` и карты зависимостей) в этот шаг не входят — это отдельное решение.

## 2. Что меняется

### 2.1. Структура
Классы — `var DivManager = class DivManager …`, наследники — `extends DivManager`; без `MooCompat`; файлы — в
`VANILLA_JS`. Интерфейс прежний:
- **`DivManager`** — `new DivManager(элемент или id)`: дерево (`TreeView`) в `#treeContainer`, разделы — запросом
  `get-data/` на языке вкладки; текущий раздел выбран и раскрыт, иначе раскрыты все; панель — внизу, «Добавить»,
  «Выбрать», «Закрыть», «Править» включены сразу, остальные — по выбору раздела (у корня — только они). Действия:
  `add` (окно добавления; ответ окна: `add` — ещё раз, `go` — переход на новую страницу, иначе перезагрузка дерева),
  `edit` (окно правки; затем `refreshNode` — имя и место раздела по `get-node-data`), `del` (подтверждение, запрос,
  перезагрузка), `up`/`down` (запрос, узел переставляется по ответу), `select` (ответ окну — данные раздела), `close`,
  `go` (двойной щелчок — переход на страницу раздела в верхнем окне). На странице (не в окне) панель растягивается под
  дерево, но не выше окна, и прокручивается в видимую часть.
- **`DivSidebar`** — дерево в боковой панели: класс `e-divtree-panel` у `html`, панель сверху, включены «Добавить» и
  «Выбрать».
- **`DivTree`** — окно выбора родителя: текущий раздел формы (`#smap_id` в окнах страницы) и его потомков выбрать
  нельзя («Выбрать» выключена).
- **`getDirsTree`** — папки репозитория (`getDirs/`) без переносимой папки и её содержимого; выбор включает
  «Перенести», запрос `…/<откуда>,<куда>/getDirsMove/`, окно закрывается.
- **Исправление:** пустой список (в репозитории нет папок, у структуры нет разделов) — пустое дерево без ошибки JS;
  прежний код падал на `treeInfo['treeRoot'].length`, и окно переноса оставалось пустым с ошибкой.
- `DivSidebar` не вызывал конструктор `DivManager` (своя настройка: без вкладок, класс у `html`): теперь конструктор
  `DivManager` зовёт метод `setup`, а `DivSidebar` его переопределяет; адрес данных дерева — метод `treeDataURL`
  (`getDirsTree` — свой). `DivManager.request` (псевдоним `Energine.request`) не используется и уходит.

### 2.2. `TreeView`
Методы с именами методов MooTools получают свои имена (после шага ни одного вызывающего на MooTools не остаётся, а
`no-traces` не отличает их от MooTools): `adopt(узел)` → **`appendNode(узел)`** (у дерева и у узла),
`addEvent(тип, обработчик)` у узла → **`on(тип, обработчик)`**. Поведение прежнее; проверки шага 4 переходят на новые
имена.

### 2.3. MooTools уходит
- Удаляются `core/modules/share/scripts/MooCompat.js` и `core/modules/share/scripts/mootools.min.js`; `setup linker`
  убирает их ссылки из `web/scripts`, `setup scriptMap` — из карты зависимостей.
- `tests/no-traces.sh`, категория `mootools`: код MooTools запрещён во всех скриптах ядра и сайта (кроме Jodit), а не
  только в списке переведённых; файлы `mootools*.js` и `MooCompat.js` — в списке мёртвых; правило «первая зависимость
  — MooCompat» уходит.
- Комментарии о MooTools в `Document.php` и `Energine.js` — по факту.

### 2.4. Что не входит
ES-модули; серверная часть структуры (в том числе `disable-output-escaping` имени раздела — отдельная задача
безопасности).

## 3. Проверки

Пишутся до переделки и проходят на нынешнем коде, кроме отмеченных:
- **MooTools нигде** (`crawl`): ни одна страница сайта и админки (гость, администратор, окна) не запрашивает
  `mootools`/`MooCompat` и не определяет `MooTools` — **красная до переделки** (структура, боковая панель).
- **Структура** (`admin/structure/`): дерево построено, текущий раздел выбран; щелчок по разделу включает кнопки, по
  корню — только свои; «Вниз»/«Вверх» (ответ сервера подменяется — порядок разделов не меняется) переставляют узел;
  «Править» — окно правки раздела, после закрытия имя узла обновлено (`get-node-data`); двойной щелчок — переход на
  страницу раздела.
- **Окно выбора родителя** (форма раздела → «…»): текущий раздел выбрать нельзя, другой — «Выбрать» возвращает его в
  форму (id, имя, сегмент).
- **Перенос файла в папку** (репозиторий, временная папка с файлом): окно папок без переносимой, выбор включает
  «Перенести», запрос `…/<откуда>,<куда>/getDirsMove/` (ответ подменяется — файл не переносится), окно закрыто; пустой
  список папок (ответ подменяется) — без ошибки JS (**красная до переделки**).
- **Файлов MooTools на сайте нет** (`public`): `scripts/mootools.min.js` и `scripts/MooCompat.js` — 404 (**красная до
  удаления**).
- **Боковая панель** (есть): дерево и окно раздела над страницей.
- `no-traces.sh` категории `mootools` — по новому правилу; файлов MooTools нет.
- Регрессия, аудиты `public`, `grids`, `editors`, `theme`, `crawl` — на стенде; после выкладки — на площадке.

## 4. Порядок работ
1. Проверки. 2. `TreeView` — новые имена; `DivManager` и наследники. 3. Удаление MooTools, `no-traces`, комментарии.
4. Документы, итоговая проверка, ревью ветки. 5. Выкладка и проверка на площадке (точка отката, код от имени web97,
`setup linker`, `setup scriptMap`; при провале — откат).

## 5. Риски
- Структура — главный инструмент администратора: ошибка ломает правку разделов. Защита — проверки структуры, окна
  выбора, боковой панели и `crawl`.
- Удаление библиотеки: страница, которая всё же опиралась на MooTools (забытый встроенный скрипт, шаблон сайта), сломается
  — защита: `crawl` (все страницы без ошибок JS), `no-traces` по всем скриптам, поиск `MooTools`/`$(`/`Asset.` в XSLT.
- Браузеры держат старые скрипты в кэше: адреса скриптов с `?v=<mtime>` (шаг 1) — после выкладки грузятся новые.

## 6. Результат
Весь JavaScript сайта и админки — без MooTools; `mootools.min.js` (160 КБ) и `MooCompat.js` удалены; этап 8 закончен.
