# Energine Simple — современный интерфейс на Tailwind: дизайн

Дата: 2026-10-05. Статус: на согласовании.

## 1. Цель и рамки

Сделать систему современной по трём направлениям, по очереди и дёшево:

- **внешний вид сайтов клиентов** — визитки из готовых секций;
- **админка** — современный вид гридов, форм, окон и панелей;
- **разработка** — единые переменные дизайна, компоненты, быстрый выпуск новой визитки.

Решения пользователя (2026-10-05):

- делаем всё, по очереди;
- сайты собирает разработчик из готовых шаблонов страниц, владелец правит только тексты и картинки — конструктора нет;
- стили — чистые утилиты Tailwind в разметке XSLT (подход «Б»), без daisyUI и подобных наборов компонентов.

Не входит:

- перестановка секций владельцем, конструктор страниц;
- новые таблицы в базе;
- изменение логики JS админки (переписана на этапах 8–9);
- Node и npm на хостинге.

## 2. Подпроекты и порядок

| № | Подпроект | Результат | Оценка |
|---|---|---|---|
| 1 | Основа: Tailwind, переменные дизайна, тема сайта | Тема сайта на Tailwind, `ui.xslt`, сборка CSS | 1–2 сессии |
| 2 | Секции визиток и шаблоны страниц | Лендинг, «Услуга», «Контакты»; демо-сайт на них | 2 сессии |
| 3 | Админка | Админка на тех же переменных и компонентах, SVG-значки | 3–4 сессии |
| 4 | Разработка (по ходу) | Чистка XSLT, выпуск новой визитки | ~1 сессия |

Порядок: 1 → 2 → 3, подпроект 4 — частями рядом с остальными. У каждого подпроекта свой план (`docs/superpowers/plans/`) и выполнение, и после каждого система рабочая.

## 3. Подпроект 1 — основа

### Сборка CSS

- **Бинарник.** Отдельный бинарник Tailwind CLI v4 (без Node и npm) — `tools/tailwindcss`. Версия закреплена, файл скачивается скриптом `tools/get-tailwind.sh` с проверкой контрольной суммы; в git — только скрипт и сумма.
- **Вход:** `site/modules/main/stylesheets/tailwind.css`:
  - `@import "tailwindcss"`;
  - `@theme` — переменные дизайна;
  - `@source` — все `*.xslt` ядра и сайта и JS, где создаются классы.
- **Выход:** `site/modules/main/stylesheets/main.css` — собранный и сжатый, лежит в git. Хостингу сборка не нужна.
- **Команда:** `php web/index.php setup css` пересобирает CSS (нужен бинарник).
- **Проверка в тестах:** собранный CSS совпадает со сборкой из исходников; иначе провал — нельзя забыть пересобрать.

### Переменные дизайна (`@theme`)

- **Состав:** цвета (основной, акцент, фон, фон приглушённый, текст, текст приглушённый, граница, ошибка, успех), шрифт, радиусы, ширина страницы.
- **Тёмная схема** — те же переменные, переопределённые по `prefers-color-scheme`.
- **Своя тема визитки** — файл переменных в `site/`, ядро не трогается.

### Компоненты XSLT

- **Где:** новый `site/modules/main/transformers/ui.xslt` — именованные шаблоны с утилитами внутри.
- **Набор:** кнопка (основная, обычная, ссылка), поле формы (подпись, ввод, подсказка, ошибка), флажок, выбор, карточка, заголовок секции, сообщение (успех, ошибка), пагинация, обёртка секции.
- **Правило:** шаблоны темы и полей сайта вызывают компоненты, а не повторяют строки утилит. Утилиты прямо в разметке допустимы только для раскладки (сетка, отступы, адаптив).

### Перевод темы сайта

- **Что переводится:**
  - `energine.xslt`: шапка, меню, переключатель языка, вход, подвал, крошки;
  - вывод полей форм сайта: вход, регистрация, профиль, восстановление пароля, обратная связь;
  - страница ошибки.
- **Что сохраняется:** функции, адреса, имена полей форм, тёмная схема, работа без JS для меню (`<details>`).
- **Админка не меняется:** её стили грузятся отдельно и только администратору. Элементные стили темы не касаются контейнеров админки (`.e-pane`, панели, окна), как сейчас.

### Проверка

- **Наборы:** регрессия, `public.js`, `theme.js`, обход — без провалов.
- **Аудит темы под новую разметку:**
  - контраст обеих схем;
  - нет горизонтальной прокрутки от 320 px;
  - видимый фокус;
  - нет внешних адресов;
  - формы доступны (`label`/`for`).

## 4. Подпроект 2 — секции визиток

### Секции

Каждая секция — именованный текстовый блок шаблона содержимого с разметкой секции из `ui.xslt`. Текст правится на странице, как сейчас.

| Секция | Содержимое |
|---|---|
| Первый экран | заголовок, подзаголовок, кнопка, картинка фона |
| Услуги | карточки: значок, название, описание |
| Цены | тарифы: название, цена, список, кнопка |
| Отзывы | цитата, автор |
| Галерея | вложения страницы (уже есть) |
| Вопросы и ответы | вопрос — ответ (`<details>`) |
| Контакты | адрес, телефон, почта; форма обратной связи |
| Призыв к действию | полоса с текстом и кнопкой |

- **Пустая секция** на сайте не выводится.
- **Новая секция** приходит с примером текста.

### Шаблоны страниц

- **«Лендинг»:** первый экран, услуги, отзывы, призыв, контакты.
- **«Услуга»:** первый экран, описание, цены, вопросы и ответы.
- **«Контакты»:** контакты, ссылка на карту.

Шаблон выбирается при создании страницы в редакторе структуры (как сейчас).

### Демо

simple.energine.org переделывается на эти шаблоны — витрина.

Изменения демо-контента — в `sql/demo.sql` и в демо-базе площадки (правило этапа 5в: переход базы тексты сайтов не переписывает).

### Проверка

- каждый шаблон страницы открывается, секции видны, пустые скрыты;
- текст секции правится на странице;
- обход и аудит темы чистые.

## 5. Подпроект 3 — админка

- **Стили.** Переменные и компоненты те же, что у сайта. Стили админки (`grid.css`, `toolbar.css`, `tabpane.css`, `controls.css`, `pagetoolbar.css`, около 2 000 строк) заменяются утилитами в XSLT и в местах JS, где создаётся разметка. Сборка админки — отдельный CSS, только для администратора.
- **Значки.** Font Awesome (шрифт и 1 800 строк CSS) заменяется набором встроенных SVG-значков (около 20).
- **Логика JS не меняется.** Меняются только классы и разметка.
- **Порядок:**
  1. окна и формы;
  2. гриды;
  3. панели;
  4. дерево структуры.
- **Проверка:** аудиты `grids.js`, `editors.js`, регрессия и обход — без провалов после каждого шага.

## 6. Подпроект 4 — разработка

- **Чистка XSLT:**
  - повторы в `fields.xslt` и `list.xslt`;
  - остатки классов Bootstrap (`btn btn-primary`, `form-horizontal`);
  - каждое `disable-output-escaping` проверяется на безопасность и при возможности убирается;
  - доступность форм.
- **Новая визитка:** `setup install`, шаблоны страниц, файл переменных темы. Инструкция `docs/NEW-SITE.md`.

## 7. Ограничения

Те же, что на этапах 1–10:

- конфиги веб-сервера не трогаются;
- владелец файлов `web97:client1`;
- пароли не попадают ни в git, ни в вывод;
- письма — только на локальный ящик;
- `web93` только читается.

Новые:

- **Бинарник Tailwind** — не в git и не нужен для работы сайта, только для пересборки CSS.
- **Без внешних адресов на страницах:** шрифты системные или локальные.
- **Тёмная схема** сохраняется.

## 8. Риски

| Риск | Что его снимает |
|---|---|
| Длинные строки утилит размножаются по шаблонам | компоненты в `ui.xslt`; утилиты в разметке — только для раскладки |
| Забыли пересобрать CSS | проверка в тестах |
| Сломана админка при смене разметки | аудиты гридов и редакторов, обход после каждого шага |
| Классы, которые создаёт JS, не попали в сборку | `@source` на JS; список безопасных классов (`@source inline`) |
| Бинарник Tailwind недоступен для скачивания | закреплённая версия, сумма; собранный CSS в git — сайт от бинарника не зависит |
