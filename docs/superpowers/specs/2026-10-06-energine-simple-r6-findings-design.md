# Energine Simple — надёжность 6: находки сравнения с xSight

Дата: 2026-10-06. Основание: анализ ядра xSight2 (предок Energine) — при сравнении нашлись слабые места нашего ядра;
пользователь ответил «сделай» на предложенный порядок: сначала эти исправления, затем чистая вставка и время блоков
в отладке, затем поиск отдельным этапом (своя спецификация).

## Цель

Убрать найденные сравнением дыры ядра — каждая проверена по коду — и добавить две дешёвые вещи из xSight. Поведение
сайта для владельца и посетителя не меняется, кроме названного ниже.

## Что меняется

1. **Цикл в дереве страниц.** Сохранение страницы на сервере отказывает (`ERR_DIV_PARENT_LOOP`), если новый родитель —
   сама страница или её потомок. Сейчас защита только в окне выбора на клиенте: страница-родитель самой себе роняет
   загрузку дерева на каждом запросе (весь сайт), цикл длиннее молча прячет поддерево.
2. **Код ответа страницы ошибки.** HTML-страница, которую не удалось построить (ошибка базы, разработчика,
   критическая — например, испорченный XML страницы), отвечает 500, а не 200. Отказы 403/404/422/503 — как прежде;
   ответы JSON админки — как прежде (их коды и тексты не трогаем).
3. **Очистка HTML без tidy.** Расширения tidy на сервере нет — «агрессивная очистка» (`site.aggressive_cleanup`,
   включена в шаблоне конфига) молча не работала. Своя очистка на `Dom\HTMLDocument` (PHP 8.4+): только мусор
   Office/Word — комментарии (в том числе условные), `<style>` с `mso-`, `<meta>`, `<link>`, `<xml>`, `<title>`,
   элементы с двоеточием в имени (`o:p`, `w:…`, `v:…` — содержимое остаётся), атрибуты с двоеточием, классы `Mso…`,
   объявления `mso-…` в `style`, `<font>` (содержимое остаётся). Текст без признаков Office не разбирается вовсе и
   остаётся байт в байт. Скрипты, iframe, значки, ссылки владельца не трогаются.
4. **Номер сессии при входе.** Вход с уже существующей сессией (cookie) получает новый номер сессии — прежний больше
   не действует (фиксация сессии). Случайный пароль при регистрации — `random_int`, а не `mt_rand`.
5. **Форма сохранения решается на сервере.** Набор полей сохранения: «правка» — если в форме есть ключ записи,
   «добавление» — если нет (а не по `componentAction` из запроса); другое имя формы принимается, только если это
   состояние конфига с полями. Состояние компонента из POST (`имя[state]`) не принимается (интерфейс его не шлёт).
   Проверка формы: необязательные поля с непустым значением проверяются (длина, шаблон); ошибки собираются все
   сразу, а не до первой.
6. **Транзакции и переадресация.** Сохранение страницы — в транзакции с откатом при ошибке; смена порядка страниц
   (два обновления) — в одной транзакции. Страница-ссылка отвечает 302 осознанно (цель владелец может сменить —
   301 браузер запомнил бы навсегда); вводящая в заблуждение установка 301 перед ней убирается.
7. **Чистая вставка в редакторе.** Jodit вставляет текст из Word и с чужих сайтов без их стилей и классов
   (`insert_clear_html` для обычной вставки и из Word); жирный, курсив, списки, ссылки остаются.
8. **Время блоков в отладке.** При `site.debug` XML страницы (`?debug`) несёт `<timings>`: на каждый компонент —
   время запуска и сборки (мс) и число запросов к базе. Сразу видно, какой блок тормозит.

## Не меняется

Модель прав, дерево, ответы JSON, вид страниц, тексты владельца без признаков Office, бюджет запросов (гость 20,
администратор 30).

## Ограничения

Общие правила площадки: конфиги веб-сервера не трогаются; владелец файлов `web97:client1` — сразу после правки
файлов, которые отдаёт nginx; живые PHP — правка в копии, `php8.5 -l`, подмена; новый API — отдельным шагом до
вызывающего кода; пароли не в git и не в выводе; письма только локально; web93 и web94 только читаются;
`rebuild.sh` не запускается; `setup` — от web97; константы — `sql/cut/stage19.sql` (повторяемый), файлы установки —
`tests/tools/regen-sql.sh`.

## Проверки

Каждое исправление — тестом, который падает до правки: `tests/page-parent.php`, `tests/error-status.php`,
`tests/html-cleanup.php`, `tests/session-id.php` (дополнение), `tests/form-state.php`, `tests/page-link.php`
(код 302), `tests/audit/editors.js` (вставка), `tests/queries.php` (время блоков). Транзакции не наблюдаемы по HTTP
без отказа базы посреди записи — проверка по коду и прежние наборы. Полный прогон, ревью Opus, один проход
исправлений.
