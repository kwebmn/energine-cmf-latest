# Energine Simple, этап 8, шаг 1 — публичный сайт без MooTools

Дата: 2026-10-02. Продолжение этапа 7 («чистое ядро», `docs/superpowers/specs/2026-10-01-energine-simple-stage7-core-design.md`).

## 1. Цель

Админка и формы сайта написаны на MooTools 1.5.2 — библиотеке, которую не развивают с 2016 года. Владелец выбрал
постепенный переход на чистый JavaScript без нового фреймворка: файл за файлом, без изменений на сервере. Этот шаг —
первый: **посетитель (гость или вошедший пользователь без прав администратора) не получает MooTools ни на одной
публичной странице**, а поведение форм для него не меняется.

Сейчас каждая публичная страница грузит `mootools.min.js` (160 КБ, 50 КБ сжатым) ради шести своих файлов (около
700 строк): `Energine.js`, `Validator.js`, `ValidForm.js`, `LoginForm.js`, `Register.js`, `UserProfile.js`.

## 2. Решения владельца

- Подход: общий код — на чистый JavaScript с прежним интерфейсом; MooTools — объявленная зависимость админских
  скриптов, документ подключает её, только если она нужна скрипту страницы (обсуждение 2026-10-02, «да»).
- Администратор на публичной странице пока получает MooTools: на ней панель правки и режим правки текста.
- Браузеры — современные (классы, `fetch`, `closest`, `classList`, `scrollIntoView` с параметрами); тема сайта уже
  рассчитана на них.
- Переход на ES-модули — в конце, когда переписана вся админка: админские скрипты держатся на глобальных объектах и
  порядке выполнения классических скриптов.

## 3. Что меняется

### 3.1. Загрузка скриптов
- `Document.php` больше не добавляет MooTools сам (сейчас — атрибут `mootools` элемента `javascript`, поддержка
  `site.js-lib` для своего адреса MooTools убирается вместе с ним, как и закомментированный пример `js-lib` в
  `configs/system.config.default.php`). MooTools — обычная библиотека в карте зависимостей
  (`system.jsmap.php`): попадает в список подключаемых библиотек, только если её требует скрипт страницы, и стоит в нём
  раньше зависящих от неё.
- Новый `core/modules/share/scripts/MooCompat.js`: зависит от `mootools.min` и несёт то, что сейчас в `Energine.js`
  нужно только рядом с MooTools, — заплатку `Array.from` (MooTools подменяет встроенную функцию, а Jodit ждёт
  стандартную) и подстановку токена `X-CSRF-Token` в `Request` MooTools.
- Каждый админский скрипт объявляет `MooCompat` первой зависимостью в `ScriptLoader.load(...)` — 23 файла;
  у `Filters`, `Overlay`, `PageList`, `TabPane`, `Toolbar`, `TreeView` такой строки нет — она добавляется. Следующие
  шаги снимают объявление с переписанных файлов; когда объявлений не останется, MooTools перестанет подключаться сама.
- `document.xslt`: настройки `Energine` — `Object.assign` вместо `Object.append`, запуск поведений компонентов —
  `document.addEventListener('DOMContentLoaded', …)` вместо `window.addEvent('domready', …)`; `<script>` MooTools
  в заголовке страницы больше нет (она приходит списком библиотек).
- **Версия в адресе скрипта.** Площадка не отдаёт `Cache-Control` и `Expires` для статики: браузер может взять из
  кэша прежний `Energine.js` (на MooTools) для страницы, где MooTools уже нет. Поэтому каждый скрипт подключается с
  `?v=<время изменения файла>`: `Document.php` пишет его в атрибут `version` каждой библиотеки и в атрибут
  `energine-version` элемента `javascript` для `Energine.js`; `document.xslt` добавляет его к адресу.

### 3.2. Общие файлы на чистом JavaScript (интерфейс прежний)
- `Energine.js` — объект `Energine` с прежними полями и функциями (`base`, `static`, `resizer`, `media`, `root`,
  `lang`, `csrf`, `singleMode`, `debug`, `translations.get/set/extend`, `request`, `resize`, `csrfInput`,
  `placeholder`, заглушка `ScriptLoader.load`). `Energine.request(uri, data, onSuccess, onUserError, onServerError,
  method)` работает через `fetch`:
  - тело — строка запроса как есть (`data` — строка, `''` или `null`; другого в коде нет), метод по умолчанию POST,
    для GET строка добавляется к адресу; `Energine.forceJSON` по-прежнему дописывает `?json`;
  - заголовки — как у `Request.JSON` MooTools: `X-Requested-With: XMLHttpRequest`, `X-Request: JSON`,
    `Accept: application/json`, `Content-Type: application/x-www-form-urlencoded; charset=utf-8` у POST, и
    `X-CSRF-Token` — сервер по `X-Request` выбирает ответ JSON;
  - обработчики — прежние: `{result: true}` — `onSuccess(response)`; ответ без `result` — текст ошибок
    (`alert`) и `onUserError(response)`; ответ не JSON — `onServerError(текст)`; код 400 и выше с `errors` в JSON
    (например, устаревшая форма — 422) — текст ошибок, без них — `onServerError(текст)`; сетевая ошибка —
    `onServerError('')`;
  - `csrfInput()` возвращает обычный элемент `input`: админские `.grab()` и `.inject()` принимают его.
- `Validator.js` — тот же класс и методы (`validate`, `validateElement`, `showError`, `removeError`, `clearErrors`,
  `scrollToElement`, `prepareFloatFields`) и тот же второй параметр — вкладки админской формы
  (`tabPane.show(tabPane.whereIs(поле))`). Правило поля — атрибуты `nrgn:pattern` и `nrgn:message`; ошибка —
  `div.error` после поля, поле — класс `invalid`, проверка повторяется при уходе с поля; прокрутка к первой ошибке —
  `scrollIntoView` (плавно, по центру), затем фокус. Текст ошибки выводится текстом, не разметкой: в переводах,
  которые попадают в `nrgn:message`, разметки нет (проверено по `sql/data.sql`), так безопаснее.
- `ValidForm.js`, `LoginForm.js`, `Register.js`, `UserProfile.js` — классы JavaScript с прежним поведением:
  проверка при отправке формы; у регистрации — проверка занятости логина при уходе с поля (POST `check/`, кнопка
  регистрации выключается, пока логин занят); у профиля — несовпадение нового пароля и повтора показывается у поля
  (`nrgn:message2`) и форма не уходит.

### 3.3. Сервер
Не меняется: разметка форм (XSLT), адреса и ответы JSON, токен формы, ловушка для ботов, лимит входов. База — тоже.

## 4. Что не входит
- Админские скрипты (кроме строки зависимости `MooCompat`) и режим правки на публичных страницах — следующие шаги.
- ES-модули, сборка, npm.
- Тема сайта и стили.

## 5. Проверки
- **Новый аудит `tests/audit/public.js`** (Playwright, как прочие): гость и вошедший посетитель на главной, `login/`,
  `register/`, `restore-password/`, `sitemap/`, `profile/`, на двух языках:
  - `mootools.min.js` не запрашивается, `window.MooTools` не определён, ошибок JS и ответов 400+ нет;
  - вход: пустая форма не уходит, у полей ошибки; верные данные — вход выполнен;
  - регистрация: неверный e-mail — ошибка у поля; занятый логин — ошибка и выключенная кнопка; свободный —
    кнопка включена;
  - профиль: несовпадающие пароли — ошибка у поля, форма не ушла;
  - скрипты страницы подключены с `?v=`.
- **Запросы админки.** В `tests/audit/grids.js` — заголовки и тело запроса `Energine.request` (грид при открытии):
  `X-Request: JSON`, `X-Requested-With`, `X-CSRF-Token`, тип тела и тело — как у прежнего `Request.JSON`. Проверка
  пишется до переделки и проходит на нынешнем коде.
- **`tests/no-traces.sh`, категория `mootools`:** в файлах, уже переписанных на чистый JavaScript (список в начале
  категории, на этом шаге — шесть файлов из раздела 1; `MooCompat.js` в него не входит — это мост к MooTools), нет
  конструкций MooTools (`new Class(`, `$(`, `$$(`, `.addEvent(`, `Request.JSON`, `Object.append`, `new Element(`,
  `.getElement`, `.inject(`, `.grab(`).
- Регрессия (17 наборов) и аудиты `crawl`, `editors`, `grids`, `theme` — на стенде, без провалов.

## 6. Порядок работ
1. Клон `private/stage8/energine` (от `5cd2be2f`), стенд `tests/tools/stand.sh`.
2. Проверки из раздела 5 — до изменений (новые падают, проверка запросов проходит).
3. `MooCompat.js`, объявления зависимости, `Document.php` и `document.xslt` (MooTools — из списка библиотек,
   версии в адресах).
4. `Energine.js` на чистом JavaScript.
5. `Validator.js`, `ValidForm.js`, `LoginForm.js`, `Register.js`, `UserProfile.js`.
6. Документы (`README.md`, `tests/README.md`), итоговая проверка на стенде, ревью ветки.
7. Выкладка — по «да» владельца: код в живое дерево, `setup linker` и `setup scriptMap`, регрессия и аудиты на
   площадке. База не меняется.

## 7. Риски
- `Energine.request` и `Validator` нужны админке: расхождение в заголовках, теле или обработке ошибок сломает гриды и
  формы. Защита — проверка запросов в `grids.js` и аудиты `editors`, `grids`, `crawl`, которые ходят через них.
- Порядок скриптов: `Energine.js` грузится раньше MooTools; ему MooTools больше не нужна, а `MooCompat.js` идёт сразу
  после неё и раньше админских скриптов (зависимость в карте).
- Кэш браузера — версия в адресе скрипта (раздел 3.1).
- Встроенные скрипты XSLT, которым нужна MooTools (`toolbar.xslt`, `file.xslt`), выводятся только в админке рядом с её
  скриптами; на публичных страницах их нет.

## 8. Результат
Публичные страницы — без MooTools (на 160 КБ меньше для каждого посетителя), шесть общих файлов — на чистом
JavaScript с прежним интерфейсом, MooTools — явная зависимость 23 админских скриптов, которая снимается по мере
следующих шагов.
