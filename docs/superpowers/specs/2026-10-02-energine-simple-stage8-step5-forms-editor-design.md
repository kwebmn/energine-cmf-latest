# Energine Simple, этап 8, шаг 5 — формы админки и визуальный редактор без MooTools

Дата: 2026-10-02. Продолжение шага 4 (`docs/superpowers/specs/2026-10-02-energine-simple-stage8-step4-filters-tree-design.md`,
выложен и проверен на площадке 2026-10-02). Владелец: «продолжай без остановки» — шаги этапа 8 идут подряд, с
выкладкой и проверкой на площадке, без отдельных согласований.

## 1. Цель

Перевести на чистый JavaScript формы админки и визуальный редактор:

| Файл | Строк | Что это | Где |
|---|---|---|---|
| `Form.js` | 641 | форма: сохранение, вкладки, проверка, визуальные поля, поля файлов, свёртывание текстовых полей | окна добавления и правки всех гридов, настройки сайта |
| `DivForm.js` | 145 | форма раздела: выбор родителя, шаблон содержимого, сброс шаблона, проверка имён | структура, боковая панель |
| `GroupForm.js` | 62 | форма роли: права на все разделы одним щелчком | роли |
| `FileRepoForm.js` | 235 | форма файла: загрузка, превью, вкладки | файловый репозиторий |
| `ImageManager.js` | 149 | окно картинки при вставке в текст: размеры, отступы, подпись | визуальный редактор |
| `EnergineEditor.js` | 173 | общая настройка Jodit, вставка картинки и файла из репозитория | визуальные поля форм, правка на странице |
| `PageEditor.js` | 170 | правка текстовых блоков на странице | режим правки |

Наследники `Form` переходят вместе с ним: класс MooTools не может наследовать класс JavaScript. Видимый итог шага —
**окна форм и режим правки работают без MooTools**. MooTools остаётся у 8 скриптов: гриды (`GridManager`,
`FileRepository`, `UserManager`, `ActionLogManager`, шаг 6) и структура (`DivManager`, `DivSidebar`, `DivTree`,
`getDirsTree`, шаг 7).

## 2. Что меняется

Классы — `var Form = class Form …`, наследники — `var DivForm = class DivForm extends Form …`; без объявления
`MooCompat`; файлы входят в `VANILLA_JS` (`tests/no-traces.sh`). Интерфейс для встроенных скриптов (`onclick` полей
файлов и сброса шаблона, `attachToolbar` панелей, запуск поведений `document.xslt`) прежний.

### 2.1. `Form`
- **`new Form(элемент или id)`** — `element`, `form` (родительская `form`, получает класс `form`), `singlePath`,
  `state` (значение `#componentAction`), `tabPane`, `validator`, `richEditors`, `overlay`, `toolbar`;
  `attachToolbar(панель)` (панель — в `.e-pane-b-toolbar` или в конец элемента; список «после сохранения» берёт
  значение из cookie `after_add_default_action`), `buildSaveURL()`, `save()`, `processServerResponse(ответ)`,
  `processServerError()`, `close()`, `clearFileField(id, ссылка)`, `processFileResult(файл, кнопка)`,
  `openFileLib(кнопка)`, `openQuickUpload(кнопка)`, `onTabChange()`; `Form.RichEditor(textarea, форма)` с
  `onSaveForm()`; `Form.Label` — `prepareLabel(адрес дерева)`, `showTree(адрес)`, `setLabel(раздел)` (подмешивается
  в `DivForm`).
- Поведение прежнее: Enter в текстовом поле не отправляет форму; пустое текстовое поле формы грида свёрнуто (`min`):
  щелчок по полю разворачивает его (`max`), щелчок по значку — сворачивает; обязательные пустые поля даты получают
  сегодняшнюю дату; вкладка с `data-src` при первом показе получает `iframe`; «Сохранить» — визуальные поля
  переносятся в `textarea`, проверка, затемнение, запрос; ответ — cookie `after_add_default_action` (сутки, путь
  сайта) и `afterClose` из списка «после сохранения», `ModalBox.setReturnValue`, окно закрывается; отказ — затемнение
  снимается. Поле файла: «…» открывает библиотеку файлов, выбранный файл — путь в поле, превью (картинка или значок);
  «Очистить» — путь пуст, превью и ссылка скрыты; «Быстрая загрузка» — окно добавления файла в папку быстрой
  загрузки, после загрузки файл находится запросом `get-data` с фильтром по id и подставляется так же.
- **Исправление:** после выбора файла появляется ссылка «Очистить» (прежний код искал её среди соседей кнопки, а она
  уровнем выше, рядом с полем, — ссылка не появлялась до перезагрузки формы).
- **Поля формы уходят строкой запроса прежнего вида** (как `toQueryString` MooTools): `input`, `select`, `textarea` с
  именем, кроме выключенных и `submit`, `reset`, `file`, `image`; флажки и переключатели — только отмеченные; у списка
  — выбранные варианты; имена и значения — через `encodeURIComponent`. `FormData` не годится: `textarea` в нём отдаёт
  переводы строк `\r\n`, и сохранённые тексты изменились бы.
- Запрос быстрой загрузки — `Energine.send` вместо `Request.JSON`. **Исправление:** затемнение снимается при любом
  ответе (прежний код оставлял его навсегда, если ответ был не из двух строк).
- **Исправление:** имя раздела, выбранного родителем, показывается текстом (прежний `innerHTML` разбирал разметку из
  имени).

### 2.2. Наследники
- **`DivForm`** — смена шаблона содержимого: сегмент из `data-segment` шаблона (поле только для чтения) или
  свободный; макет из `data-layout` (кроме `*`); поле XML раздела очищается и прячется. `resetPageContentTemplate()` —
  запрос `reset-templates/<id>/`, у варианта шаблона снимается пометка изменения, поле XML очищается и прячется.
  `save()` — пустое имя на вкладке языка (раздел на этом языке не выключен) — предупреждение `ERR_NO_DIV_NAME`, без
  запроса. Окно выбора родителя — `prepareLabel('list/')`.
- **`GroupForm`** — переключатель в строке «Все разделы» отмечает весь свой столбец прав.
- **`FileRepoForm`** — как сейчас: загрузка во временный файл через `fetch`, превью, маленькие изображения, вкладка
  «Маленькое изображение» включается после загрузки картинки, причина отказа — у поля.
- **`ImageManager`** — как сейчас: данные картинки из окна-родителя (`ModalBox.getExtraData`), смена ширины или
  высоты пересчитывает другую по пропорции, путь — через `resizer`, превью; «Вставить» возвращает картинку.

### 2.3. `EnergineEditor`, `PageEditor`
- **`EnergineEditor.make(элемент, {singlePath, jodit})`** — как сейчас: Jodit с набором кнопок, своими «картинка» и
  «файл» из репозитория; стили Jodit — один раз через `Energine.loadCSS`; `jodit` дополняет настройки по верхним
  ключам (`Object.assign`; прежний `Object.merge` сливал вглубь, но вызывающий передаёт только плоские ключи).
- **`new PageEditor()`** — блоки `.nrgnEditor`, `PageEditor.BlockEditor(блок)`: сохранение при уходе из блока, маяк при
  уходе со страницы, пометка и предупреждение при отказе — как сейчас.

### 2.4. Cookie — в `Energine`
`Energine.readCookie(имя)`, `Energine.writeCookie(имя, значение, {path, domain, days})` — значения через
`encodeURIComponent`, как у `Cookie` MooTools. `PageToolbar` переходит на них (его собственные помощники уходят);
`Form` — тоже. Путь сайта — каталог адреса `Energine.base`.

### 2.5. Встроенный скрипт панели формы и грида (`toolbar.xslt`)
Строки на MooTools (`document.id`, `getElement`, `getSize`, `getComputedSize`) считали высоту содержимого, но её
применение закомментировано — блок уходит. Без этого окна форм без MooTools падали бы после привязки панели.

### 2.6. Неиспользуемое уходит
`Form.request` (псевдоним `Energine.request`; `DivForm` зовёт `Energine.request` сам), `glow`, `appendedControls`,
`textBoxes`; запуск `ColorPicker` (класс нигде не определён: поле цвета — столбец `_color` — уронило бы форму; таких
столбцов нет); закрытие окна по Esc (обработчик ждал `keypress`, а браузеры не посылают его для Esc — он не работал;
окна по Esc не закрываются, шаг 2); `Form.Label.restoreLabel` и cookie `last_selected_smap` (читал только он, а его
никто не вызывает); `GroupForm.uncheckGroupRadio` (не подключён, ссылается на неопределённую переменную).

### 2.7. Что не входит
Гриды (шаг 6), структура (шаг 7), серверная часть форм.

## 3. Проверки

Пишутся до переделки и проходят на нынешнем коде, кроме отмеченных (аудит `editors`):
- **Форма пользователя** (правка временного пользователя): Enter в текстовом поле не отправляет форму; поле аватара —
  выбор файла в библиотеке подставляет путь и превью, **после выбора видна «Очистить» (красная до переделки)**,
  «Очистить» всё убирает; «Быстрая загрузка» — загруженный файл подставлен в поле, затемнение снято.
- **Вкладка со своей страницей** (настройки сайта, «Дополнительные параметры»): iframe при первом показе, один.
- **Строка запроса формы**: поля с `[]`, юникодом, `&`, `+`, `%`, переводом строки, флажки, список с несколькими
  вариантами, выключенные поля — как у `toQueryString` MooTools.
- **Сохранение из грида** (шаблоны писем): «после сохранения» — «Править следующий»: окно закрывается, cookie
  `after_add_default_action` записана с путём сайта, грид открывает правку следующей записи; шаблон не изменился.
- **Форма раздела** (раздел `features/content`): текстовое поле свёрнуто, щелчок разворачивает, значок сворачивает;
  смена шаблона — сегмент и макет из шаблона, поле XML скрыто и пусто; выбор родителя в окне дерева — id в поле,
  имя в подписи, **имя с разметкой — текстом (красная до переделки)**; пустое имя на вкладке языка — предупреждение,
  запроса нет; сброс изменённого шаблона — пометка снята, поле XML скрыто; раздел после проверок восстановлен.
- **Форма роли**: переключатель «Все разделы» отмечает весь столбец.
- **Окно картинки**: смена ширины пересчитывает высоту, путь через `resizer`, превью обновлено.
- **Без MooTools** — форма пользователя, форма раздела, форма роли, форма файла, окно картинки, режим правки:
  `MooTools` не определена и `mootools.min.js` не запрашивается — **красная до переделки**; стили Jodit — один раз.
- `no-traces.sh`, категория `mootools`: семь файлов шага — в `VANILLA_JS`.
- Регрессия, аудиты `public`, `grids`, `editors`, `theme`, `crawl` — на стенде; после выкладки — регрессия и аудиты на
  площадке.

## 4. Порядок работ
1. Проверки. 2. Cookie в `Energine`, `EnergineEditor`, `PageEditor`. 3. `Form` с наследниками и встроенный скрипт
панели. 4. Документы, итоговая проверка, ревью ветки. 5. Выкладка и проверка на площадке (точка отката, код от имени
web97, `setup linker`, `setup scriptMap`; при провале — откат).

## 5. Риски
- Формы — во всех окнах добавления и правки: ошибка ломает правку всего. Защита — `editors`, `grids`, `crawl` (все
  формы админки без ошибок JS).
- Строка запроса формы иного вида исказила бы сохраняемые данные. Защита — «сохранено без правки — как было» (шаблон
  письма, раздел), регрессия.
- Окно формы возвращает ответ гриду на MooTools (`ModalBox.setReturnValue`): ответ — обычный объект, грид читает
  `afterClose`. Защита — проверка сохранения из грида.

## 6. Результат
Формы админки, визуальный редактор и правка на странице (около 1 580 строк) — на чистом JavaScript; окна форм и
режим правки — без MooTools; MooTools остаётся у 8 скриптов гридов и структуры.
