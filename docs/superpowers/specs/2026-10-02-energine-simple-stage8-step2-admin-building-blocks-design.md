# Energine Simple, этап 8, шаг 2 — основа админки без MooTools: затемнение, окна, вкладки, листалка

Дата: 2026-10-02. Продолжение шага 1 (`docs/superpowers/specs/2026-10-02-energine-simple-stage8-public-without-mootools-design.md`,
выложен и проверен на площадке 2026-10-02).

## 1. Цель

После шага 1 MooTools нужна только админке: 23 файла, около 8 000 строк. Переход идёт файл за файлом, снизу вверх по
зависимостям. Шаг 2 переводит на чистый JavaScript четыре основных элемента, которыми пользуются остальные скрипты
админки. Ни один из них никого не наследует, и их никто не наследует:

| Файл | Строк | Что это | Кто пользуется |
|---|---|---|---|
| `Overlay.js` | 114 | затемнение страницы (и знак загрузки) | `ModalBox`, `Form`, `GridManager`, `PageEditor` |
| `ModalBox.js` | 273 | окна админки (`iframe` поверх страницы), общие для вложенных окон | 25 вызовов `open` в 7 скриптах |
| `TabPane.js` | 250 | вкладки форм и гридов | `Form`, `GridManager`, `DivManager`, `Validator` |
| `PageList.js` | 230 | листалка страниц грида | `GridManager` |

Администратор не должен заметить разницы, кроме исправлений из раздела 3.3. MooTools в админке остаётся: её требуют
19 других скриптов.

## 2. Дорожная карта этапа 8 и выбор подхода

Подходы:
- **А. Снизу вверх, интерфейс сохраняется (выбран).** Сначала элементы, от которых зависят другие; скрипты на
  MooTools пользуются ими как прежде. Шаги маленькие, каждый проверяется отдельно.
- **Б. Сверху вниз, семействами.** Например, `Form` со всеми наследниками и зависимостями сразу. Шаги крупнее; к тому
  же класс MooTools не может наследовать класс JavaScript (`Extends`), так что основа и наследники должны переходить
  вместе.
- **В. Всё сразу** — отвергнут: 8 000 строк одним шагом не проверить.

Шаги по подходу А (каждый — своя спецификация и ваше «да»):
- шаг 2 (этот) — `Overlay`, `ModalBox`, `TabPane`, `PageList`;
- шаг 3 — `Toolbar`, `Filters`, `TreeView` (около 2 400 строк);
- шаг 4 — семейство `Form` (`Form`, `FileRepoForm`, `DivForm`, `ImageManager`, `GroupForm`) с `EnergineEditor`,
  `PageEditor`, `PageToolbar`;
- шаг 5 — семейство `GridManager` (`FileRepository`, `UserManager`, `ActionLogManager`);
- шаг 6 — семейство `DivManager` (`DivSidebar`, `DivTree`, `getDirsTree`); затем `MooCompat.js` и `mootools.min.js`
  уходят совсем, скрипты переходят на ES-модули.

## 3. Что меняется

### 3.1. Четыре файла на чистом JavaScript, интерфейс прежний

Классы — `var Имя = class Имя …`; без объявления `MooCompat`; файлы входят в список `VANILLA_JS` (`tests/no-traces.sh`).
Обработчики, которые потребители передают параметрами (`onPageSelect`, `onTabChange`), вызываются как раньше.
`addEvent` на этих объектах никто не вызывает — общего механизма событий MooTools не нужно.

- **`Overlay(родитель, {opacity = 0.5, duration = 500, indicator = true})`** — `show()`, `hide()`, `element`.
  Родитель по умолчанию — `body` верхнего окна. Появление и исчезновение — плавные, 0,5 с; после исчезновения элемент
  убирается со страницы. Знак загрузки — класс `e-overlay-loading`, как прежде.
- **`ModalBox`** — общий объект (`window.top.ModalBox`): `init()`, `open({url, post, code, onClose, extraData})`,
  `close()`, `getCurrent()`, `getExtraData()`, `setReturnValue(значение)`, `initialized`, `boxes`. Окно — `div.e-modalbox`
  с `iframe.e-modalbox-frame`; `post` уходит в окно формой (с токеном, как сейчас); первое окно показывает
  затемнение, последнее закрытое — убирает. Щелчок по затемнению окно не закрывает — так попросил клиент.
- **`TabPane(элемент, {onTabChange})`** — `element`, `tabs`, `currentTab`, `show(вкладка)`, `getTabs()`,
  `whereIs(поле)`, `enableTab(номер)`, `disableTab(номер)`. Разметка и классы прежние (`ul.e-tabs`, `li.current`,
  `li.disabled`, `div.e-pane-item`); у вкладки — `data` (из `span.data`) и `pane`, у панели — `tab`. При смене
  вкладки фокус переходит в первое текстовое поле, как раньше. Данные вкладки (`{ lang: N }` — язык вкладки в формах
  и гридах с полями на разных языках) прежний код разбирал через `eval` (запись без кавычек — не JSON); теперь
  `list.xslt` и `form.xslt` пишут их как JSON (`{"lang": N}`), а `TabPane` читает `JSON.parse`.
- **`PageList({onPageSelect})`** — `build(страниц, текущая)`, `enable()`, `disable()`, `getElement()`, `currentPage`.
  Разметка прежняя (`ul.e-pane-toolbar.e-pagelist`, `li[index]`, `li.current`, стрелки), при одной странице листалка
  скрыта, при выключенной — полупрозрачна и не реагирует.

Неиспользуемое уходит: `Overlay.isVisible`, `PageList.selectPageByNum`, `TabPane.createNewTab`, `setTabTitle`,
`getCurrentTab` (вызовов нет), закомментированная ветка `form` в `ModalBox.open`.

### 3.2. Стили элементов

Сейчас стили (`modalbox.css`, `tabpane.css`, `pagelist.css`) подгружает вставка Energine в собранном `mootools.min.js`
(`Asset.css`: `Energine.static + 'stylesheets/' + имя`, один раз). Для файлов без MooTools — то же самое в `Energine.js`:
`Energine.loadCSS(имя)`. Вставка в `mootools.min.js` остаётся для скриптов на MooTools; если файл уже подключён
ссылкой, второй раз он не грузится.

### 3.3. Исправления по пути

- **Ошибка под полем убирается и при вставке и автозаполнении** (отложенное замечание шага 1): `Validator` снимает
  ошибку не только по нажатию клавиши, но и по событию `input`. Кнопка формы больше не уезжает из-под щелчка.
- **Esc окно не закрывает — как сейчас на деле.** Старый код хотел закрывать окно по Esc, но слушал `keypress`
  (Chrome его для Esc не присылает) и добавлял слушатель при каждом открытии. Клиент просил не закрывать окно
  случайно (щелчок по затемнению отключён — «выйти без сохранения изменений?»), поэтому слушатель убирается, а
  поведение остаётся прежним. Если нужно закрытие по Esc — это отдельное решение владельца.

### 3.4. Что не входит

Остальные 19 скриптов админки, удаление MooTools, ES-модули, разметка и стили (кроме записи данных вкладки,
раздел 3.1), сервер.

## 4. Проверки

Пишутся до переделки и проходят на нынешнем коде (кроме проверки по разделу 3.3):
- **Листалка** (`grids.js`): грид с записями больше, чем на одну страницу (временные пользователи `grids-db.php`) —
  листалка видна, щелчок по странице 2 показывает другие строки и отмечает страницу текущей, на последней странице
  нет стрелки «дальше», во время загрузки затемнение грида есть, после — убрано.
- **Вкладки** (`editors.js`): в форме с вкладками щелчок по вкладке показывает её панель и прячет прежнюю, у вкладки
  класс `current`; вкладка с классом `disabled` не переключается; ошибка на неоткрытой вкладке её открывает (шаг 13).
  В гриде с вкладками языков (их выводит `list.xslt` для гридов с полями на разных языках) смена вкладки
  перезагружает данные на языке вкладки (`onTabChange` получает `{lang}`).
- **Окна** (`grids.js`): «Настройки сайта» с панели страницы открывают окно и затемнение, кнопка «Закрыть» окна
  убирает и окно, и затемнение; `modalbox.css` подключён один раз; ничего от окна не остаётся в документе. Возврат
  значения из окна (`setReturnValue` → `onClose`) и окно с `post` — «картинка из репозитория» (`editors.js`, есть).
- **Esc** (`grids.js`): при открытом окне Esc его не закрывает.
- **Ошибка под полем** (`public.js`): после пустой отправки формы входа значение, вставленное без нажатия клавиш,
  сразу убирает ошибку (красная до правки `Validator`).
- `no-traces.sh`, категория `mootools`: четыре файла — в `VANILLA_JS`.
- Регрессия, аудиты `public`, `grids`, `editors`, `theme`, `crawl`, `install-check`, `fresh-check` — на стенде.

## 5. Порядок работ

1. Проверки из раздела 4.
2. `Energine.loadCSS`, `Overlay`, `ModalBox`.
3. `TabPane`, `PageList`.
4. `Validator` — событие `input`.
5. Документы, итоговая проверка, ревью ветки.
6. Выкладка — по «да» владельца: код в живое дерево, `setup linker`, `setup scriptMap`; регрессия и аудиты на
   площадке. База не меняется.

## 6. Риски

- Скрипты на MooTools вызывают методы MooTools у элементов, которые отдают эти файлы (`tabPane.element.getElement`,
  `pageList.getElement().inject`). Это работает, пока MooTools загружена: она расширяет встроенные прототипы
  элементов. Сами четыре файла на MooTools не опираются.
- `ModalBox` общий для окон: объект из верхнего окна вызывают скрипты внутри `iframe`. Это обычные вызовы методов;
  параметры приходят из другого окна — так и сейчас.
- Порядок загрузки: `ModalBox.init` срабатывает на `DOMContentLoaded` раньше запуска поведений страницы (файл
  загружается в заголовке, его слушатель регистрируется раньше).

## 7. Результат

Четыре основных элемента админки (около 870 строк) — на чистом JavaScript; MooTools остаётся у 19 скриптов, которые
следующие шаги переводят тем же способом.
