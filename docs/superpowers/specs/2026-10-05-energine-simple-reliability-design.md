# Energine Simple — надёжность и будущее: дизайн

Дата: 2026-10-05. Статус: утверждено пользователем («приступай»).

## 1. Откуда

Три разбора 2026-10-05 (ядро PHP, JavaScript, второй проход по xsight; все выводы перепроверены по коду):

- переписывать ядро или JS целиком не нужно; главный рычаг «в будущее» — статический анализ, которого нет совсем;
- найдены дефекты важнее любого переписывания: потеря текстов на других языках при очистке блока, удаление
  страницы со всем поддеревом и системных разделов, данные запроса в SQL строкой (админка), непойманный
  `\Throwable` при включённом `display_errors`, `?struct` для гостя, заброшенный `timthumb` с внешними источниками,
  двойное сохранение формы, тихий сбой без JSON, нерабочий сброс фильтра, апостроф в переводе кнопки панели;
- из xsight стоит взять: безопасное удаление, историю текста с откатом, язык «в подготовке», выбор страницы для
  ссылки, память старых адресов (301), памятку владельцу из справки, `setup check`, картинку через ресайзер,
  шаблон подстраниц по умолчанию; необязательно — контактную форму с сохранением заявок.

## 2. Этапы (по очереди, инлайн, у каждого свой план)

1. **Периметр и защита от потери данных** — этот этап.
2. **Статический анализ:** PHPStan (phar в `tools/`, уровень 2 с базовой линией, в регрессии), JSDoc + `tsc --noEmit`,
   мёртвый код JS (~200 строк).
3. **Владельцу:** история текста и откат, сохранение как событие (журнал, дата страницы), язык «в подготовке»,
   выбор страницы для ссылки в редакторе, памятка `setup manual`, `setup check` перед сдачей.
4. **Ядро:** `Db` под фасадом `QAL`, кэш схемы таблиц и `enum FieldType`, типизированный реестр без `__get`,
   `Translator` одним запросом.
5. **Адреса и интерфейс:** память старых адресов (301), `/about` → `/about/`, грид на CSS, `<dialog>`-оболочка
   окон, свой ресайзер на GD вместо `timthumb`.

Не делаем: Twig/Latte вместо XSLT, DI-контейнер, TypeScript со сборкой, Web Components, отказ от iframe в окнах,
замену Jodit, HTML-кэш для гостей.

## 3. Ограничения

Те же, что раньше: конфиги веб-сервера не трогаются; владелец `web97:client1`; пароли не в git и не в выводе;
письма только локально; web93 только читается; `rebuild.sh` не запускается; команды `setup` — от `web97`.
Поведение сайта меняется только там, где этап это называет; полный прогон после каждой задачи.
