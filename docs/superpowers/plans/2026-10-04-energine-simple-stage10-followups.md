# Energine Simple — этап 10: доделки. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (выбор пользователя — инлайн). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Закрыть дефекты, найденные по ходу этапов 2–6 и ещё живые после этапов 7–9: сначала то, что видят посетитель, администратор и владелец, затем установщик и гигиена.

**Architecture:** Точечные правки в существующем коде. Каждая правка — с проверкой, которая сначала падает. Новые константы и данные — в `sql/cut/stage10.sql`, файлы установки — генератором `tests/tools/regen-sql.sh`; генератор должен применять все `sql/cut/stage*.sql` начиная с 6-го.

**Tech Stack:** PHP 8.5, MariaDB 10.11, XSLT 1.0, чистый JS (ES-модули), bash, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-26-energine-simple-design.md` (разделы 7–8); источник задач — сверка 64 отложенных мелочей (2026-10-04, scratchpad `minors-all.txt`) и пункты отчёта «Что решить вам» 7–9.

## Global Constraints

Те же, что на этапах 1–9:
- конфиги веб-сервера не трогаются;
- владелец файлов `web97:client1`;
- пароли не попадают ни в git, ни в вывод;
- письма — только на локальный ящик;
- `web93` только читается;
- `rebuild.sh` не запускается;
- база площадки меняется только скриптом `sql/cut/stage10.sql`.

## Review Focus

1. Посетитель не видит текста внутренних ошибок (SQL, пути) вне режима отладки — ни на странице ошибки, ни в JSON.
2. Аккаунт нельзя увести из чужой сессии: смена логина (e-mail) требует текущего пароля.
3. После регистрации в почте нет рабочего пароля; посетитель задаёт его по одноразовой ссылке.
4. Снятые формой флажки robots страницы снимаются; поля, которых в форме нет, не стираются.
5. Установщик не портит сайт: запуск от root — отказ, процедуры проверяются до первого изменения базы.

### Task 1: Безопасность посетителя и учётной записи

- [ ] Страница ошибки и JSON вне отладки: для ошибок кроме 404/403/422 и ошибок проверки — общий текст «Ошибка на сервере», подробности — только в журнал (сверка №43).
- [ ] Профиль: смена `u_name` — только с верным текущим паролем (№24).
- [ ] Регистрация: e-mail проверяется на сервере (`filter_var`), длина ≤ 50 (№25).
- [ ] Сообщение «пользователь уже есть» — без разметки из ввода: экранирование или без `disable-output-escaping` (№26).
- [ ] «Настройки сайта»: сохранение без номера записи — отказ, второй записи сайта не бывает (п. c).
- Проверки: `smoke-profile.php`, `smoke-mail.php` / `smoke-antispam.php`, новый `smoke-errors.php`, `site-settings.php`.

### Task 2: Формы страницы и вход

- [ ] Форма страницы: снятые флажки `smap_meta_robots` дают пустой набор, только если форма это поле содержит (п. a).
- [ ] Главная: флажок «Показывать в меню» не выводится (№6).
- [ ] Кнопка входа: без подсказки «Click me» (№33).
- [ ] `auth.php` без Referer и без `return`: переадресация на страницу входа, а не пустая страница (№35).
- Проверки: `smoke-write.sh`, `smoke-csrf.php` или новый шаг в нём.

### Task 3: Регистрация без пароля в письме

- [ ] После регистрации письмо содержит одноразовую ссылку установки пароля — механизм восстановления (`u_restore_hash`, срок), а не пароль. Шаблон `user_registration` и константы — в `stage10.sql` и `data.sql` (пункт отчёта 7).
- Проверки: `smoke-mail.php` — в письме нет пароля, ссылка задаёт пароль, вход им.

### Task 4: Визуальный редактор

- [ ] Сбой загрузки Jodit не ломает форму: поле остаётся обычным `textarea` (№15).
- [ ] Ссылка на файл сохраняет оформление выделения (№11).
- [ ] Очищенный блок сохраняется пустым, без `<p><br></p>` (№12).
- Проверки: `tests/audit/editors.js`.

### Task 5: Установщик

- [ ] Запуск от root — отказ с подсказкой `runuser -u <владелец>` (№51).
- [ ] До первого изменения базы: право создавать процедуры (создать и удалить пробную функцию) и `ctype` (№47, №54).
- [ ] Соединение — фиксированный `sql_mode` (№48).
- [ ] Текст сбоя: «удалите таблицы этой установки» вместо «очистите базу» (№46); после сбоя — подсказка следующего шага (№45).
- [ ] `setup demo`: проверка пустоты по всем таблицам демо, копирование файлов проверяется (№49).
- Проверки: `tests/tools/install-check.sh`.

### Task 6: Гигиена и итог

- [ ] Гостям не грузятся модули формы входа компактной формы, если они не нужны (№41) — только если правка локальна, иначе ruling.
