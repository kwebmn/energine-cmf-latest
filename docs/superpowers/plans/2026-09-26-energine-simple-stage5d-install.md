# Energine Simple — этап 5г: установщик и сводная база. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Установка форка одной командой CLI в пустую базу — схема, базовые данные, администратор, статика; демо-контент — отдельной командой; база площадки и установка с нуля совпадают.

**Architecture:**
- **Сводные файлы базы** (заменяют восемь файлов полной системы и переходные скрипты для новых установок):
  - `sql/structure.sql` — схема форка: 31 таблица (28 по спецификации и 3 мультисайта до этапа 6) и 5 хранимых процедур, без `DEFINER` и счётчиков `AUTO_INCREMENT`;
  - `sql/data.sql` — базовые данные пустого сайта: языки (ru, ua), сайт, служебные страницы (главная, админка с разделами, вход, регистрация, восстановление пароля, профиль, карта сайта, google-sitemap, robots.txt), группы и права, все переводы, почтовые шаблоны, корневые папки файлового репозитория;
  - `sql/demo.sql` — демо-контент `simple.energine.org` поверх базовых данных: разделы и тексты, новости, галерея, обратная связь с получателями, демо-посетители, файлы репозитория; сами файлы — `sql/demo/uploads/` (≈1 МБ, в git).

  Файлы получаются один раз генератором из базы, поставленной старым путём (временный экземпляр `fresh-check.sh`), строки — с явными ключами и в порядке ключа, так что отпечатки совпадают. Генератор — вне репозитория, в рабочей папке этапа: после перехода старого пути нет.
- **Установщик** — `php web/index.php setup install` (только CLI, как сейчас):
  1. проверяет расширения PHP (pdo_mysql, xsl, dom, mbstring, gd, openssl, fileinfo);
  2. берёт параметры: конфиг площадки, если он уже есть, иначе — пишет его из шаблона `configs/system.config.default.php` (`--domain`, `--db-host`, `--db-name`, `--db-user`, `--db-socket`; режим 600; ссылка `web/system.config.php`); `--config=ПУТЬ` — другой файл конфига (для проверок);
  3. всё проверяет до первого изменения базы: база пуста, e-mail администратора корректен, пароли есть;
  4. ставит `structure.sql` и `data.sql`;
  5. создаёт администратора (`--admin-email`, `--admin-name`, по умолчанию `Admin`) в группе администраторов;
  6. записывает домен сайта (`http` и `https`) в `share_domains`;
  7. раскладывает статику (`linker`, `scriptMap`); `--no-static` — без неё (проверки).

  Пароли не передаются в аргументах (их видно в `ps` и истории): пароль базы — `ENERGINE_DB_PASSWORD`, администратора — `ENERGINE_ADMIN_PASSWORD`; без переменной и при терминале — запрос без эха, иначе — отказ. Пароли не печатаются. `setup demo` загружает `demo.sql` и копирует `sql/demo/uploads` в `web/uploads` (с `--no-static` — без файлов). `bootstrap.php` пускает `setup` и без конфига площадки (установка его ещё не написала).
- **Сокет базы:** `database.socket` в конфиге — и для установщика, и для ядра (`Registry::getDB`); без него — `host`/`port`, как сейчас.
- **Проверка установки** — `tests/tools/install-check.sh` на временном экземпляре MariaDB (база площадки не трогается):
  - установка в пустую базу, повторная — отказ без изменений;
  - базовая установка отвечает: встроенный сервер PHP от имени `web97` на `127.0.0.1` с копией точки входа и временным конфигом — главная, вход, регистрация, восстановление пароля, карта сайта, админка после входа, 404;
  - `setup demo` поверх — отпечаток совпадает с базой площадки.
- **Тесты и инструменты:** `fresh-check.sh` ставит базу новым путём (установщик и демо); отпечаток сверяет пользователей и их группы по логину — номер администратора зависит от порядка установки. `rebuild.sh` — через установщик, без архива загрузок с `web93`. Восемь файлов полной системы и списки `sql/cut/*.files` удаляются; `sql/cut/*.sql` остаются — это переход базы полной системы на форк, из них же `no-traces.sh` берёт списки удалённых переводов.

**Tech Stack:** PHP 8.5, MariaDB 10.11, bash, curl.

**Spec:** `docs/superpowers/specs/2026-09-26-energine-simple-design.md` — раздел 4 «Установка», раздел 5, раздел 8.

## Global Constraints

Те же, что на этапах 1–5в:
- конфиги веб-сервера не трогаются;
- владелец `web97:client1`, git от root, после него `chown`;
- PHP — `php8.5`;
- пароли не попадают ни в git, ни в вывод, ни в аргументы команд;
- письма — только на `web97@loki.kweb.biz`;
- `web93` только читается;
- `rebuild.sh` не запускается (пароль тестового администратора меняет только пользователь), база площадки проверками установки не трогается — только временный экземпляр MariaDB;
- после правки PHP — пауза перед проверкой (opcache).

## Review Focus

1. **Установка в непустую базу:** отказ до любого изменения — чужой сайт в той же базе цел; сообщение говорит, что делать.
2. **Пароли:** не видны в `ps`, истории, выводе установщика и журналах; конфиг — режим 600.
3. **Пустой сайт после установки работает:** страницы системы открываются, админка пускает администратора, переводы на месте, ссылок на демо-разделы нет.
4. **Демо поверх установки = база площадки** (отпечаток), картинки демо на месте (обход без 404).
5. **Прерванная установка:** ошибка в данных (e-mail, нет пароля, нет расширения) ловится до первого изменения базы; упавший на середине SQL установщик говорит, как начать заново (очистить базу).

Тесты — `install-check.sh` (1, 2, 3, 5), `fresh-check.sh` и обход (4).
