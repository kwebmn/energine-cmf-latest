# Energine Simple — удобство, этап 1: чистка без риска. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (инлайн). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Убрать из системы то, что только мешает:
- неиспользуемые константы перевода;
- лишние ключи шаблона конфига;
- тихий `DBWorker::__call`;
- мелкие классы-прослойки с одним вызовом.

**Architecture:**
- **Константы.**
  - Инструмент `tests/tools/unused-constants.php` собирает используемые имена:
    - литералы `[A-Z][A-Z0-9_]+` в `core`, `site`, `setup`, `htdocs` (PHP, XSLT, JS, XML);
    - `FIELD_<колонка>` для каждой колонки каждой таблицы базы;
    - `CONTENT_<шаблон>` для каждого файла шаблона;
    - `TXT_SECTION_SAMPLE_*`;
    - константы из значений конфига.
  - Остальные константы удаляет переход `sql/cut/stage12.sql` (повторяемый, `DELETE … WHERE ltag_name IN (…)` с переводами). Файлы установки пересобирает генератор.
- **Конфиг.**
  - Удаляются:
    - ключи `project`, `site.useTimer` вместе с таймером в `htdocs/index.php`;
    - `site.asXML` (XML документа остаётся по `?debug` при `site.debug`);
    - образец `site.vars` вместе с кодом в `Document.php`.
  - `thumbnails` в шаблоне — пустой массив с комментарием, как добавить размер. Вкладка превью в форме файла исчезает, если размеров нет.
  - Конфиг площадки не трогается: код терпит старые ключи.
- **`DBWorker::__call`:** неизвестный метод — `\BadMethodCallException`. Вызовы, которые раньше молча давали `false`, находятся полным прогоном и исправляются явно.
- **Прослойки.** Каждый класс с одним вызывающим и логикой меньше ~40 строк вливается в вызывающий код, если тот от этого не усложняется. Иначе класс остаётся, решение пишется в журнал. Кандидаты: `Link`, `IRQ`, `XMLTransformer`, `JSONTransformer`, `SimplestBuilder`, `EmptyBuilder`, `JSONDivBuilder`, `PageStructureDocument`. `SiteManager` (около 30 вызовов) не трогается.

**Tech Stack:** PHP 8.5, MariaDB, XSLT, bash.

**Spec:** `docs/superpowers/specs/2026-10-05-energine-simple-convenience-design.md` (раздел 2, этап 1).

## Global Constraints

- Конфиги веб-сервера не трогаются; владелец `web97:client1`; пароли не в git и не в выводе; письма только локально; web93 только читается; `rebuild.sh` не запускается.
- База площадки меняется только переходом `sql/cut/stage12.sql`.
- Конфиг площадки (с паролем базы) не читается и не правится.
- Поведение сайта и админки не меняется. Исключения:
  - вкладка превью файла исчезает, если размеров превью нет;
  - заголовок `X-Timer` больше не отправляется.

## Review Focus

1. **Константа, имя которой собирается в коде из частей** (кроме `FIELD_`) — `ERR_`, `TXT_` с суффиксом, `BTN_` по id кнопки, `CONTENT_`, `LAYOUT_`, `MSG_`. Её не удалить по ошибке.
2. **Код, который полагался на тихий `false` от `__call`** (вызов несуществующего метода), начинает падать там, где тесты не ходят.
3. **Старый конфиг площадки с удалёнными ключами** (`asXML`, `useTimer`, `vars`, `thumbnails` с восемью размерами) по-прежнему работает.
4. **`raw-constants.php`:** число подписей, видных системными именами, не растёт после удаления констант.

Проверки:
- п. 1, 4 — `tests/raw-constants.php`, `bash tests/no-traces.sh` (i18n), обход админки `crawl.js` с проверкой «нет системных имён» в интерфейсе (если её нет — добавить в задачу 1);
- п. 2 — полный прогон и поиск вызовов несуществующих методов статически: `grep` вызовов `->имя(` по методам классов;
- п. 3 — `install-check`, площадка с её конфигом.
