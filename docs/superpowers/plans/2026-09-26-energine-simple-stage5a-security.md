# Energine Simple — этап 5а: безопасность. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Закрыть пункты раздела 7 спецификации, кроме почты:
- CSRF-токен во всех POST-формах;
- лимит попыток входа;
- восстановление пароля по одноразовой ссылке;
- honeypot и минимальное время заполнения;
- экранирование HTML в гридах админки.

Сверка установки с нуля идёт на временном экземпляре MariaDB: живая база и пароль администратора не затрагиваются.

**Architecture:**
- **Сверка установки с нуля** — `tests/tools/fresh-check.sh`:
  - поднимает временный `mariadbd` той же версии: каталог данных во временной папке, свой сокет, без TCP;
  - заливает в него файлы установки в порядке `docs/INSTALL.md`;
  - повторяет то, что `setup install` делает с базой: строки `share_domains` и `share_domain2site`;
  - снимает отпечаток `fingerprint.php` с временной базы и с живой, сравнивает их, останавливает экземпляр и удаляет его каталог.

  `rebuild.sh` остаётся для настоящей переустановки площадки и на этом этапе не запускается.
- **CSRF** — gear `Energine\share\gears\Csrf`:
  - `Csrf::token()`: `sha256('energine-csrf|' . ключ)`. Ключ — идентификатор сессии, если посетитель вошёл, иначе случайное значение из cookie `nrgn_csrf`. Cookie создаётся при первом обращении: HttpOnly, SameSite=Lax, Secure на HTTPS, живёт до закрытия браузера.
  - `Csrf::verify()`: для POST токен берётся из поля `csrf_token` или заголовка `X-CSRF-Token` и сравнивается через `hash_equals`. Если есть заголовок `Origin`, его хост должен совпадать с хостом запроса.
  - Проверка — в одном месте ядра, `DocumentController::run` перед запуском компонентов, и в `auth.php`. Отказ — 403 с текстом `ERR_CSRF`. Для JSON-запросов — ответ, который админка показывает как ошибку.
  - Токен выводится так:
    - свойство документа `csrf`;
    - в `document.xslt` — `<meta name="csrf-token">` и `Energine.csrf`;
    - скрытое поле `csrf_token` во всех шаблонах `<form method="post">`;
    - в JS — заголовок у всех `Request` MooTools, у `fetch` и в теле `sendBeacon`, поле в формах, которые создаёт JS.
  - Cookie сессии получает флаги HttpOnly, SameSite=Lax и Secure на HTTPS.
- **Лимит попыток входа** — таблица `user_login_attempts` (IP, логин, время). Правило: 5 неудач на логин или 20 неудач с одного IP за 15 минут — следующая попытка отклоняется без проверки пароля, с текстом `ERR_TOO_MANY_ATTEMPTS`. Успешный вход очищает неудачи этого логина. IP — `REMOTE_ADDR`: `X-Forwarded-For` подделывается.
- **Восстановление пароля** — `RestorePassword`:
  1. Запрос по e-mail. Ответ всегда один: `MSG_RESTORE_LINK_SENT`. Если адрес есть, создаётся токен из 32 случайных байт. В `user_users` пишутся `u_restore_hash` (sha256 токена) и `u_restore_until` (+1 час). Письмо `user_restore_password` уходит со ссылкой `[restore_link]`. Повторный запрос раньше чем через 5 минут письмо не шлёт.
  2. Переход по ссылке `…/restore-password/reset/<токен>/` — форма нового пароля с подтверждением. Если ссылка неверна или просрочена — `ERR_RESTORE_LINK`.
  3. Отправка формы:
     - пароль меняется;
     - токен стирается;
     - сессии пользователя удаляются;
     - показывается `MSG_PASSWORD_CHANGED`.

     До перехода по ссылке старый пароль работает.
- **Honeypot и минимальное время** — `Energine\share\gears\FormGuard`, вызывается в `Register` и `FeedbackForm`:
  - компонент отдаёт атрибут `antispam` со временем показа формы;
  - `form.xslt` выводит поле-ловушку `hp_url` (скрыто inline-стилем, `tabindex="-1"`, `autocomplete="off"`) и скрытое `form_ts`;
  - при сохранении: непустая ловушка, нет `form_ts` или прошло меньше 3 секунд — отказ `ERR_FORM_SPAM`. Форма возвращается с введёнными данными.
- **Экранирование в гридах** — `GridManager.iterateFields`: значения текстовых типов выводятся как текст (`set('text')`), не как HTML. Сначала сверяется, какие гриды нарочно получают разметку с сервера.
- **База.**
  - Изменения идут в `sql/cut/stage5.sql` и повторный прогон его не меняет:
    - таблица `user_login_attempts`;
    - две колонки `user_users`;
    - тексты письма `user_restore_password` (ru, ua);
    - новые переводы;
    - удаление переводов, которые больше не используются.
  - Сводная схема — этап 5г.

**Tech Stack:** PHP 8.5, MariaDB 10.11, MooTools, XSLT, bash, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-26-energine-simple-design.md` — раздел 5 (колонки
восстановления пароля, `user_login_attempts`), раздел 7, раздел 8.

## Global Constraints

Те же, что на этапах 1–4:
- конфиги веб-сервера не трогаются;
- владелец файлов `web97:client1`, git работает от root, после него `chown`;
- PHP — `php8.5`;
- пароли не попадают ни в git, ни в вывод команд;
- письма уходят только на `web97@loki.kweb.biz`;
- `web93` только читается;
- коммиты делаются с явными путями.

Особое:
- **`rebuild.sh` не запускается и `tests/local.php` не переписывается**, пока пользователь не решит судьбу утёкших паролей. Сверка установки с нуля — только через `fresh-check.sh` на временном экземпляре.
- **Временный `mariadbd`:**
  - запускается без сети (`--skip-networking`), с данными во временной папке;
  - после проверки останавливается, каталог удаляется;
  - системный MariaDB и его конфиги не трогаются.
- Тесты, которые создают пользователей, попытки входа и токены, убирают их за собой.

## Review Focus

1. **Все законные POST работают с токеном.** Проверяются:
   - гриды и формы админки: сохранение, удаление, перемещение, загрузка файла, вложения, переводы, языки, роли, права;
   - режим правки: сохранение блока и маяк при уходе;
   - вход и выход, регистрация, восстановление пароля, обратная связь, профиль.

   Тест — регрессия, `editors.js`, `grids.js`, обход.
2. **Форма, открытая до входа или выхода, при отправке даёт понятное сообщение, а не белую страницу.** JSON-запрос без токена даёт ошибку, которую показывает админка. Тест — `smoke-csrf.php`.
3. **Лимит входа не запирает администратора после пары опечаток и не срабатывает на прогонах тестов.** Сообщение понятное, через 15 минут вход снова открыт. Тест — `smoke-login-limit.php`, регрессия.
4. **Ссылка восстановления пароля:**
   - работает на обоих языках;
   - одноразовая, с истекающим сроком;
   - не подходит к другой учётной записи;
   - старый пароль действует, пока ссылкой не воспользовались;
   - неизвестный адрес получает тот же ответ, письма нет.

   Тест — `smoke-mail.php`, раздел восстановления.
5. **HTML посетителя в гридах админки показывается текстом.** Сообщения обратной связи и имена пользователей не исполняются. Флажки, картинки и даты в гридах не ломаются. Тест — `grids.js`.

### Task 2: CSRF-токен

  - администратор: сохранение формы новости через JSON без токена — отказ JSON-ом, запись не изменилась; с токеном — сохранено, прежний текст возвращается;
  - чужой `Origin` при верном токене — отказ;
  - токен гостя после входа не подходит, токен со страницы после входа — подходит.
- [ ] `tests/testlib.php`: `http()` для POST сама добавляет заголовок `X-CSRF-Token`. Токен берётся со страницы (`<meta name="csrf-token">`) и обновляется, когда меняется cookie сессии. `smoke-write.sh` — то же для curl.
