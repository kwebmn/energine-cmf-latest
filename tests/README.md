# Проверка площадки

Сценарные тесты и обход браузером. Все создаваемые записи называются `claude-test*`
и удаляются самими тестами, поэтому наборы можно гонять повторно.

## Откуда тесты берут адрес, базу и пароли

- **Адрес сайта, база и пути** — из конфига площадки `web/system.config.php`
  (на ISPConfig `web/` лежит рядом с `private/`). Другой конфиг задаётся переменной
  `ENERGINE_CONFIG`.
- **Логин и пароль администратора, почтовый ящик** — из `tests/local.php`. Файл в git
  не попадает, образец — `local.php.example`.
- `tests/env.php` собирает всё это вместе. PHP-наборы подключают его через `testlib.php`,
  bash-скрипты — через `envsh=$(php8.5 env.php --shell) || exit 1; eval "$envsh"`: если
  настройки собрать не удалось, скрипт останавливается сразу.
- **Токен формы.** Каждый POST сайта требует токен посетителя (этап 5а). `http()` из
  `testlib.php` добавляет его сама — заголовок `X-CSRF-Token` со страницы, заново после
  входа и выхода; пустой заголовок `X-CSRF-Token: ` отправляет запрос без токена. Наборы
  со своим curl (`smoke-roundtrip.php`, `smoke-editing.php`, `smoke-final.sh`,
  `smoke-write.sh`) берут токен из `<meta name="csrf-token">` сами.

Пароли в коде тестов не пишутся никогда. Хук `.githooks/pre-commit` отклоняет коммит,
если в нём оказался пароль из конфига площадки или из `local.php`. Подключается один
раз на клон: `git config core.hooksPath .githooks`.

## Стенд

`tests/tools/stand.sh` поднимает сайт из этого репозитория без площадки: временная MariaDB (сокет, без сети),
установка с демо, встроенный сервер PHP на 127.0.0.1 — с каркасом загрузок, адресами ресайзера, пределами PHP-FPM
и каталогом `tmp` рядом с `web` (там `install-check.sh` держит временные базы), как у площадки. Конфиг, база и файлы
площадки не читаются.

```sh
STAND_MAILBOX=<локальный ящик> bash tests/tools/stand.sh start
bash tests/tools/stand.sh run bash tests/regression.sh
bash tests/tools/stand.sh stop
```

`run` задаёт для `env.php` адрес, конфиг, учётные данные и каталог `web` стенда (`ENERGINE_BASE`,
`ENERGINE_CONFIG`, `ENERGINE_LOCAL`, `ENERGINE_WEB`), а PDO и клиенту `mariadb` — сокет базы стенда.
Клон репозитория для работы со стендом кладут на уровень глубже `private/` (например, `private/stage7/energine`):
без переменных стенда `env.php` такого клона не находит конфиг площадки и останавливается.

## Полный прогон

```sh
bash tests/regression.sh
```

Порядок такой:
1. чтение всех страниц гостем и администратором (`smoke-final.sh`);
2. правка через админку: разделы, тексты, файлы, пользователи;
3. токен формы (`smoke-csrf.php`);
4. профиль (`smoke-profile.php`);
5. идентификаторы сессий (`session-id.php`);
6. адрес сайта из конфига: хост без порта, домен cookie, корень (`site-address.php`);
7. поля даты — встроенные поля браузера (`field-dates.php`): дата и время через T принимаются;
8. «Настройки сайта» (`site-settings.php`): одна запись, сохранённое видно посетителю, `NOINDEX`
   закрывает `robots.txt` и `google-sitemap`, без токена — отказ;
9. права без сайтов (`smoke-rights.php`): группа с правом правки раздела шаблонов писем видит все
   шаблоны, форма группы сохраняет права;
10. меню по флагу страницы (`menu.php`);
11. почта: регистрация, восстановление пароля по ссылке, шаблоны писем;
   отказы ловушки для ботов (`smoke-antispam.php`); отправка через SMTP (`smoke-smtp.php`);
12. лимит попыток входа (`smoke-login-limit.php`) — последним: он запирает IP этой машины и
   убирает за собой;
13. новые строки журнала ошибок PHP за время прогона.

Норма — ноль расхождений во всех 17 наборах и пустой журнал.

**Почта.** Письма тестов уходят только на локальный ящик площадки (`mailbox` в `local.php`,
на simple.energine.org — `web97@loki.kweb.biz`): тестовые регистрации и восстановления пароля
идут на этот адрес. **Наружу тестовые письма слать нельзя.**

**Порядок страниц.** Добавление страницы через админку сдвигает `smap_order_num` всему
сайту — так устроено ядро. Прогон запоминает порядок разделов перед началом и возвращает
его в конце; `smoke-write.sh`, который добавляет страницу, делает то же сам, так что и
одиночный его запуск не оставляет сдвига.

Наборы пишут рядом с собой файлы cookie и временные ответы, в git они не попадают.
Если прогон шёл от root, после него нужно вернуть владельца площадки, на ISPConfig это
`chown -R webNN:client1 /var/www/clients/client1/webNN/private`.

## Отдельные наборы

- `smoke-final.sh` — только чтение, безопасен на живой площадке.
- По областям: `smoke-write.sh`, `smoke-roundtrip.php`, `smoke-editing.php`,
  `smoke-upload.php`, `smoke-profile.php`, `smoke-mail.php` (регистрация, восстановление
  пароля, шаблоны писем).
- После прерванного прогона остатки почтового набора убирает `cleanup-mail.php`.
- Безопасность (этап 5а):
  - `smoke-csrf.php` — POST без токена, с чужим токеном или чужим `Origin` отклоняется
    кодом 422 с понятным текстом, JSON-ом для админки; вход без токена не выполняется;
    токен гостя после входа не подходит; возврат после входа — только на свой сайт;
    удаление и выключение пользователя GET-ом отклоняются;
  - `smoke-login-limit.php` — 5 неудач на логин с одного IP и 20 с IP закрывают вход на 15 минут,
    неудачи с чужого IP вход не закрывают, удачный вход очищает неудачи своего IP,
    заблокированный пользователь не входит;
  - `smoke-antispam.php` — отказы регистрации: заполненная ловушка, нет времени показа,
    отправка раньше 3 секунд; писем набор не шлёт (удачная регистрация — в `smoke-mail.php`,
    который ждёт 3 секунды, как человек), а его регистрации идут на локальный ящик;
  - восстановление пароля по ссылке проверяет `smoke-mail.php`: запрос не меняет пароль,
    ссылка одноразовая и со сроком, неизвестный адрес получает тот же ответ, сессии
    закрываются после смены пароля;
  - `smoke-profile.php` — профиль временного посетителя: в форме нет служебных полей
    (активность, ссылка восстановления), пароли не обязательны, имя сохраняется без пароля,
    поля не из формы не сохраняются, пароль меняется только с верным текущим паролем и
    совпадающим повтором, дата рождения — встроенное поле даты, его значение сохраняется;
    `smoke-mail.php` — регистрация сохраняет только поля формы,
    повторная регистрация того же логина отклоняется без письма.
- `smoke-smtp.php` — почта через SMTP (этап 5б): `Mail` и `SmtpTransport` против поддельного
  сервера `tools/fake-smtp.php` (без шифрования, STARTTLS, SSL, AUTH PLAIN и LOGIN, неверный
  пароль, недоступный сервер, нет STARTTLS, непроверенный сертификат, перевод строки в адресе,
  регистр и опечатка в `encryption`, отправитель с именем и получатели списком, данные вслед за
  ответом на STARTTLS, строка длиннее 998 октетов — части письма в quoted-printable)
  и postfix этой машины через `127.0.0.1` — письмо в локальный ящик. Конфиг площадки не
  трогается: `mail.smtp` задаётся в памяти процесса. Все адреса теста локальные.
- `field-dates.php` — шаблоны полей даты без поднятого ядра (этап 7): дата и время из
  встроенного поля браузера (через T, с секундами и без) и прежняя запись через пробел
  принимаются, дата без времени и пустое обязательное — нет; поле даты — ГГГГ-ММ-ДД.
- `no-traces.sh` — в коде и базе нет следов вырезанного: модулей (этап 1), частей apps
  (этап 2), share (этап 3), прежних редактора и загрузчика файлов (этап 4), мультисайта (этап 6),
  модуля apps, галереи и вложений, прежних редактора кода и календаря, мёртвого кода ядра (этап 7), а в
  справочнике — их переводов. Категория `mootools` (этап 8): в файлах, уже переписанных на чистый JavaScript
  (список `VANILLA_JS`), нет конструкций MooTools, а у остальных скриптов первая зависимость — `MooCompat`.
  Запуск целиком или по частям: `no-traces.sh [code|db|all] [категория...]`,
  категории перечислены в начале файла.
  Код выхода 2 — проверка не выполнена: база недоступна или поиск по коду завершился
  ошибкой (например, сломано выражение). Такой прогон не считается ни зелёным, ни красным.
- `raw-constants.php` — какие подписи видны системными именами; сравнивается до и после
  чистки переводов.
- `menu.php` — главное меню строится по флагу страницы `smap_in_menu`: гость видит на двух
  языках страницы с флагом и не видит служебных, флажок снимается и в форме раздела, у
  новой страницы он включён, у администратора есть подменю админки.
- `setup-linker.sh` проверяет, что `setup linker` не трогает модули в `core/modules`.
- `env-guard.sh` — bash-наборы останавливаются, если `env.php` не собрал настройки.
- `hook-selftest.sh` — хук `pre-commit` ловит пароль в коммите (во временном репозитории).

## Инструменты чистки

- `tools/cut-constants.php` — какие переводы остались только у вырезанного: сравнивает
  слова удалённых файлов и таблиц с оставшимся кодом и базой. Удалённые строки
  изменённых файлов передаются так же, файлом (`git diff … | grep '^-'`). Слова из
  комментариев и сторонних библиотек не в счёт, в том числе в явно переданных файлах. Его список становится блоком удаления переводов
  в `sql/cut/stageN.sql`. Чего инструмент не видит:
  - строки, которых не было ни в каком коде, — их ищут по именам вырезанного в справочнике;
  - строки, которые буквально стояли только в удалённом коде, но собираются из обычного
    слова оставшегося кода (`TXT_CONTENT`), — их ищут как буквальные имена удалённого кода,
    которых нет в оставшемся, и проверяют, что их не собирает `'TXT_' . …`.
- `tools/fingerprint.php` — отпечаток базы по таблицам: данные без колонок, которые
  меняются от установки к установке, и схема (колонки, индексы, внешние ключи). Им
  сверяется база после переходного скрипта с установкой с нуля.
- `tools/tempdb.sh` — временный `mariadbd` для проверок установки (свой каталог и сокет, без
  сети, настройки сервера площадки) и копия точки входа площадки, из которой установщик
  работает от имени владельца площадки; подключается через `source`. Путь сокета ограничен
  107 символами.
- `tools/install-check.sh` — сам установщик на временном экземпляре: установка в пустую базу
  (21 таблица — без мультисайта, модуля apps и вложений разделов; процедуры, языки, администратор с проверкой пароля
  по хэшу, адрес сайта в конфиге — домен с портом и корень, конфиг с режимом 600, служебные
  страницы без демо-строк, пароли не в выводе); отказы до изменений
  (непустая база, неверный e-mail, нет пароля); пустой сайт отвечает через встроенный сервер
  PHP (главная, вход, регистрация, восстановление пароля, карта сайта, 404, админка после
  входа; `<base>` и форма входа — адрес из конфига и при чужом `Host`; cookie на адресе с портом —
  без `Domain`); установка со статикой (ссылки, карта скриптов; модуль в конфиге без каталога —
  `setup linker` отказывается, не очистив статику); установка с доменом площадки и демо поверх
  совпадает с базой площадки.
  `INSTALL_DEBUG=каталог` сохраняет страницы 404 и админки и журнал сервера.
- `tools/fresh-check.sh` — сверка установки с нуля с базой площадки, не трогая её:
  `setup install` с доменом площадки и `setup demo` во временном экземпляре, затем отпечатки.
  Выход 0 — совпало, 1 — различия (печатаются таблицы), 2 — проверка не выполнена.
  `FRESH_OUT=каталог` сохраняет оба отпечатка, `FP_ROWS=таблица` — строки вместо хэшей.
- `tools/migration-check.sh` — переход базы на форк (`sql/cut/stage5.sql`) на временной
  базе со своим содержимым сайта: тексты сайта не меняются, страницы со сброшенным XML
  названы в выводе, повторный прогон ничего не меняет. Переход на этап 6 (`stage6.sql`) — с базы
  этапа 5г (файлы установки коммита, записанного в скрипте) с демо-контентом и свойствами сайта:
  разделы с адресами, права, тексты и новости те же, своё значение свойства сайта важнее общего,
  таблиц и колонок мультисайта нет, повтор ничего не меняет, два сайта или два корня — отказ.
  Переход на этап 7 (`stage7.sql`) — с базы до этапа 7 с демо и своими разделами (свой XML и своя
  раскладка с удалёнными компонентами, живой компонент с похожим именем, удалённые шаблоны): таблиц apps и вложений нет,
  разделы админки новостей и обратной связи и их письма удалены, разделы новостей, обратной
  связи, галереи и со своим XML — текстовые страницы и названы в выводе (раздел галереи со
  вторым текстовым блоком — отдельно), тексты те же, повтор ничего не меняет.
- `tools/regen-sql.sh` — файлы установки (`sql/structure.sql`, `data.sql`, `demo.sql`) из перехода:
  нынешние файлы во временный экземпляр, поверх `sql/cut/stage7.sql`, выгрузка в прежнем формате.
  Изменение базы пишется один раз — в переходе; каждая строка базы попадает в `data.sql` или
  `demo.sql`, иначе отказ. `REGEN_NO_MIGRATION=1` — без перехода (файлы выходят те же).
- `tools/rebuild.sh --yes-drop-everything` — **снимает всю базу площадки** и ставит заново
  установщиком (`setup install` с конфигом площадки, `setup demo`) с новым случайным паролем
  администратора в `local.php`. Только для стенда.
- Справочник переводов `fingerprint.php` сравнивает по имени константы: если на базе
  площадки тесты добавляли и удаляли переводы, счётчик автоинкремента там выше, и новая
  константа скрипта получает другой `ltag_id`. Пользователей и их группы — по логину: номер
  администратора зависит от порядка установки. Остальные таблицы сравниваются целиком.

## Обход браузером

```sh
cd tests/audit
( envsh=$(php8.5 ../env.php --shell) && eval "$envsh" \
  && node crawl.js crawl-guest.txt crawl-admin.txt crawl-singles.txt out.json )
```

Скобки — подоболочка: пароли из `env.php` не остаются в окружении терминала и не
подхватятся следующими командами.

Обход проходит гостем на двух языках, администратором и по формам добавления и правки
всех гридов. Главная обходится всегда: пустых строк в списках нет, а её путь пустой.
Так же главную читают `smoke-final.sh` и `raw-constants.php`. Обход ищет ошибки
JavaScript, необработанные исключения и ответы с кодом 400+.
Нужны Playwright и Chrome. Путь к модулю Playwright задаётся переменной `PLAYWRIGHT`,
по умолчанию берётся кеш `npx`. Списки адресов — пути от корня сайта, при появлении
новых разделов их правят руками.

## Тема

```sh
cd tests/audit
( envsh=$(php8.5 ../env.php --shell) && eval "$envsh" && node theme.js )
```

`theme.js` открывает страницы всех типов — главная, текстовая, подразделы, карта сайта, вход,
регистрация, восстановление пароля, профиль (под
временным посетителем из `theme-db.php`), 404 — на телефоне (390 px) и десктопе (1280 px):
- нет горизонтальной прокрутки, `main#content` в исходном порядке раньше боковой колонки,
  один `h1`, ссылка «к содержимому» — первая по Tab, фокус виден;
- меню на телефоне свёрнуто и открывается кнопкой, на десктопе видно сразу;
- ничего со сторонних адресов, без ошибок JS и 404; тёмная схема меняет фон.

Отдельно: в форме регистрации поля видны, подписи над ними, ловушка для ботов спрятана; страница
ошибки сайта (форма регистрации без токена, 422) и страница `ErrorDocument` (ссылка на удаление
пользователя GET-ом) — в каркасе темы, с текстом и ссылкой на главную; подпункт меню виден при
наведении и с клавиатуры; админка внутри страницы сайта темой не затронута. Снимки экрана — в каталог `SHOTS` (по умолчанию
временный, путь печатается). Страницу 404 на этой площадке подменяет ISPConfig
(Own Error-Documents): такие проверки печатаются как SKIP.

## Публичные страницы без MooTools

```sh
cd tests/audit
( envsh=$(php8.5 ../env.php --shell) && eval "$envsh" && node public.js )
```

`public.js` (этап 8) открывает гостем и временным посетителем (`public-db.php`, логин с «+») главную, вход,
регистрацию, восстановление пароля, карту сайта и профиль на двух языках: MooTools не запрашивается и не
определена, у скриптов сайта версия `?v=`, ошибок JS и ответов 400+ нет. Формы: пустая форма входа не уходит, у
полей ошибки, с данными посетителя вход выполнен (логин и пароль тест набирает по клавише, как человек); в
регистрации неверный e-mail отмечен, занятый логин (с «+») — ошибка и выключенная кнопка, свободный — кнопка
включена; в профиле разные новый пароль и повтор — ошибка у поля, форма не уходит; значение, вставленное без
клавиш, сразу убирает ошибку поля. Посетитель удаляется.

## Гриды админки

```sh
cd tests/audit
( envsh=$(php8.5 ../env.php --shell) && eval "$envsh" && node grids.js )
```

`grids.js` кладёт разметку (`<img onerror>`, `<b>`) в имя пользователя и название файла
(`grids-db.php`) и проверяет гриды «Пользователи», файловый репозиторий и дерево страниц:
разметка показана текстом, не разобрана и не исполнена, флажки, превью и ссылки гридов на
месте. Ещё: дерево разделов и окно выбора родителя в форме раздела — без выбора сайта;
фильтр журнала действий по дате — встроенное поле даты, находит записи дня (запись теста) и
не находит чужих; «Настройки сайта» с панели страницы. Запросы админки (`Energine.request`): заголовки и тело —
как у прежнего запроса MooTools, отказ сервера (чужой токен, 422) — текст отказа и обработчик ошибки формы; панель
грида привязана к гриду. Затемнение: показать — убрать — показать подряд оставляет его видимым, убранное уходит со
страницы. Грид переводов: листалка (на странице 2 другие строки; пока страница грузится, грид затемнён, а листалка
не реагирует; на последней странице нет стрелки «дальше»), вкладка языка перезагружает строки на этом языке; грид в
одну страницу — без листалки. Окна «Настройки сайта»: Esc их не закрывает, окно в окне закрывается по одному,
«Закрыть» убирает окно и затемнение, стили окон подключены один раз. Панель страницы у администратора на главной:
рамки, значок, боковая панель и её cookie, MooTools не загружается, окна с панели (переводы, языки, пользователи,
роли, файлы, настройки) строят свои гриды. Панель грида: выключенная кнопка ничего не делает, включённая открывает
окно. Кнопки панели: выключенная в описании, выключенный переключатель, выпадающий список. Фильтр грида
пользователей в окне: панель открывается и закрывается ссылкой, «+» и «−» фильтров, значение с «+» находит своего
пользователя, «Сбросить» возвращает все строки. Дерево структуры: выбор раздела, раскрытие папки по значку; узлы на
своём дереве: классы, «вверх» и «вниз», путь к узлу, удалённый узел уходит из списка. Записи теста удаляются.

## Редакторы и загрузка

```sh
cd tests/audit
( envsh=$(php8.5 ../env.php --shell) && eval "$envsh" && node editors.js )
```

`editors.js` проверяет в браузере:
- Jodit в форме раздела (описание): текст со ссылкой сохраняется, поля, которых не касались, остаются как были;
- правку на странице: блок сохраняется при уходе из него и, маяком, при уходе со страницы;
  блок, который сервер не сохранил, помечен, администратор предупреждён, правка уходит позже;
- существующую разметку — карта во `iframe`, скрипт, значок `<i>`, `<b>`, ссылка
  `target="_blank"`, текст вне абзаца: без правки ничего не сохраняется, после правки разметка
  на месте — на странице и в форме;
- поле кода шаблона письма — обычное `textarea` моноширинным шрифтом, сохранение без правки
  ничего не меняет;
- кнопки «Картинка из репозитория» и «Файл из репозитория»: окно библиотеки и то, что они
  вставляют (картинка с размерами, `alt` и отступами; ссылка на файл с выделением и без;
  после отмены — ничего), в форме и на странице;
- загрузку файла в репозиторий через `fetch`: превью и имя подставлены, отказ сервера показан
  у поля; файл больше допустимого — причина с размером; ответ не JSON — текст с кодом ответа;
  причина с `<` и `&` — как есть, текстом; после неудачи форма забывает файл;
- форму с вкладками: пустое обязательное поле на неоткрытой вкладке — форма не уходит, вкладка открывается,
  у поля ошибка; щелчок по вкладке показывает её панель, прячет прежнюю, фокус — в первое поле;
- вкладку «Маленькое изображение» формы файла: выключена до загрузки картинки, после — открывается;
- панель формы: список «после сохранения» берёт значение из cookie, нажатие мыши на кнопку не уводит фокус из поля;
- переключатель «Режим правки»: нажат в режиме правки, повторный щелчок из него выходит.

Всё изменённое тест возвращает (тексты — полными снимками через `editors-db.php`), после
прогона база совпадает с установкой с нуля (`tools/fresh-check.sh`).
